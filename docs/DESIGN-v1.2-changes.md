### 0.1 v1.1 과 정면으로 부딪히는 두 건

v1.1 은 지도교수 의견으로 3D 를 통째로 걷어냈고(§1.1), 아동 불안을 이유로 경고음을
금지했다(§3.7). 의견 13과 9는 그 둘을 되돌린다. **코드보다 설계서를 먼저 고친다**는
원칙(`CLAUDE.md` §9)에 따라 여기서 조건을 붙여 다시 연다.

| | v1.1 | v1.2 | 되돌리지 않는 부분 |
|---|---|---|---|
| 3D | 전면 금지 | **리플레이 화면에 한해 허용** | 에디터·게임·인쇄는 그대로 2D SVG 하나(`ui/PlanSvg.tsx`)를 쓴다 |
| 소리 | 경고음 금지 | **감지기 소리·음성 허용** | 붉은 점멸 금지는 유지. 소리는 끌 수 있고, 실패를 알리는 데 쓰지 않는다 |

이 조건이 지켜지는 한 v1.1 의 취지(인지 부담·성능·번들·1인 개발 범위)는 유지된다.
근거는 §3, §7 에 적는다.

## 1. 그리기 편의 (FR-7 계열 보강)

### 1.1 FR-7.3 개정 — 문 후보를 눈에 띄게

문 후보의 "문?" 글자가 8px 이었다. 열 살 아이가 도면 위에서 못 찾는다.

- 글자 **13px 굵게**, 흰 테두리를 둘러 도면 위에서 읽히게 한다
- 후보 배지를 세로 18px → **24px**, 후보 전체의 누르는 판은 여전히 셀 한 칸 이상
- 쉬움 수준에서는 "문?" 대신 **"여기 문?"** 으로 무엇을 묻는지 분명히 한다

### 1.2 FR-7.13 신규 — 시작 평면 8종

3종(방2·방3·단독)은 "우리 집과 비슷한 것"을 고르기에 모자란다. **8종**으로 늘린다.

| id | 이름 | 설명 |
|---|---|---|
| `apt_2room` | 방 두 개 아파트 | (기존) |
| `apt_3room` | 방 세 개 아파트 | (기존) |
| `house_1f` | 단독주택 | (기존) |
| `apt_4room` | 방 네 개 아파트 | 4베이 판상형. 발코니가 길다 |
| `apt_tower` | 타워형 아파트 | 복도가 짧고 방이 둘러싼다. 대피공간이 있다 |
| `studio` | 원룸 | 방 하나 + 욕실. 현관이 곧 부엌이다 |
| `villa` | 빌라·다세대 | 계단이 집 앞에 붙는다 |
| `duplex` | 복층 | 위·아래를 한 도면에 나란히 놓고 계단으로 잇는다 |

- 8종 전부 **§3.5 플레이 가능성 보장**과 **P3(critical 을 다 푸는 길 존재)** 를 통과해야 한다.
  `tools/kids-tests.ts` 가 평면 수 × seed 100 을 돈다.
- 고르는 화면은 8종 + 빈 도면 = 9칸이므로 **격자를 세 줄까지** 늘리고 스크롤을 둔다.

### 1.3 결함 — 빈 도면에서 아무것도 그릴 수 없다

**증상**: "직접 그릴래요"를 고르면 1층 물음 다음에 `mySpot` 단계로 간다. 그런데
`KidsCanvas.onDown` 은 `mySpot` 단계에서 모든 클릭을 `pickMyRoom` 으로 보내고,
빈 도면에는 방이 없으므로 "방 안을 눌러 줘"만 반복된다. 팔레트로 방을 놓을 수도 없다.

**고침**: 온보딩이 끝날 때 도면에 방이 없으면 `mySpot` 을 건너뛰고 `edit` 로 간다.
캐릭터가 "먼저 방을 하나 놓자"고 말하고 팔레트의 방을 가리킨다.
**첫 방이 놓이는 순간** 비로소 `mySpot` 으로 넘어가 "네 방은 어디야?"를 묻는다.
빈 도면에서 시작해도 온보딩 흐름이 끊기지 않는다.

### 1.4 FR-7.14 신규 — 필수 물건과 그 밖의 물건

**필수(required)** 는 대피계획을 세우는 데 없으면 안 되는 것이다. 없으면 게임을 막지 않고
(D5 — 미완성이어도 진행 가능) **놓기 전에 알려 준다**.

| 구분 | 항목 |
|---|---|
| **필수** | 현관문, 내 자리, 방문(방마다 하나), 소화기, 감지기 |
| **있을 수 있는 것** | 창문, 발코니창, 침대, 소파, 책상, 옷장, 책장, 식탁, 냉장고, TV, **싱크대**, **컴퓨터**, 가스레인지, 보일러, 멀티탭, 난로, 초 |

- `content/blocks.json` 에 `required: true|false` 를 더한다.
- 팔레트에서 필수 항목은 **왼쪽 위에 작은 채움 표시**를 달고, 아직 도면에 없으면 표시가 비어 있다.
  색만으로 구분하지 않는다 (P4).
- **사전에 걸러 주는 장치**: 점검 막대(`.k-report`) 옆에 `필수 3/5` 를 늘 띄우고,
  「대피 연습 시작!」을 누르는 순간 빠진 필수가 있으면 **한 번 물어본다**.
  "소화기랑 감지기가 아직 없어. 그냥 해 볼래, 놓고 올래?" — 막지 않고 고르게 한다 (D5).
- 조작 수를 늘리지 않는다 (FR-7 우선). 물음은 **한 번뿐**이고 "그냥 해 볼래"가 기본 초점이다.

### 1.5 FR-7.15 신규 — 물건 두 가지 추가

`sink`(싱크대), `computer`(컴퓨터)를 `FurnitureKind` 에 더한다. 둘 다 SVG 로 그린다.
싱크대는 부엌의 표준 배치라 `kitchen` 템플릿에 미리 놓는다.

## 2. 개구부 상태 모델 (의견 12)

### 2.1 데이터 모델 변경

`OpeningBlock.closedByDefault: boolean` 은 있었지만 **편집 화면에서 바꿀 수 없었고,
게임은 문만 보고 창은 늘 열린 것으로 쳤다.** 다음으로 고친다.

```ts
export interface OpeningBlock {
  ...
  /** 평소 닫아 두는가. 게임 시작 때 openingState 의 초깃값이 된다 */
  closedByDefault: boolean;
}
```

`GameState.doorState` 를 **모든 개구부**로 넓힌다. 이름은 `doorState` 를 유지한다
(저장 파일 호환. §7.4 의 이행 규칙을 건드리지 않는다).

### 2.2 확산 반영

`core/hazard/transfer.ts` 의 `transfer()` 는 지금 닫힌 **문**만 막는다. 프리셋이 주는
감쇠 계수를 개구부 종류별로 나눈다. 엔진에 재난 이름은 여전히 들어가지 않는다 (FR-8.16).

| 개구부 | 열림 | 닫힘 | 근거 |
|---|---|---|---|
| 방문·중문 | 1 | `doorClosedFactor` (0.06) | 기존 |
| 현관문(방화문) | 1 | `sealedClosedFactor` (0.02) | 방화문은 일반 문보다 훨씬 잘 막는다 |
| 비상구 | 1 | `sealedClosedFactor` | 〃 |
| 창·발코니창 | 1 | `glazedClosedFactor` (0.03) | 유리는 연기를 막지만 열에 깨진다 |

- **창은 열려 있으면 확산을 돕는다.** 프리셋에 `openWindowBoost`(1.25)를 두어 열린 창을
  건널 때 계수를 올린다. "창문 닫고 나가기"가 화면에서 실제로 이득이 되게 한다.
- 사람의 통행(`walkable`)은 지금과 같다. 닫힌 문은 열고 지나갈 수 있다.

### 2.3 화면 표현

`OpeningArt` 는 이미 `open` 을 받는다. 편집 화면에서도 넘겨서 **평소 상태를 늘 보이게** 한다.

- **열림** — 문짝이 안쪽으로 열린 선, 벽 자리는 비어 있다
- **닫힘** — 벽 자리를 굵은 선이 막고, 문짝 선은 가늘다
- **현관문(방화문)** — 닫힘일 때 초록 굵은 선 + 바깥쪽에 짧은 이중선
- **창** — 닫힘이면 유리선 두 줄, 열림이면 한 줄이 옆으로 밀려 있다

### 2.4 조작 (조작 수를 늘리지 않는다)

- 개구부를 고르면 선택 막대에 **"평소 닫아 둠 / 열어 둠"** 토글이 뜬다. 한 번 누르면 바뀐다.
- 새로 놓는 개구부의 기본값: 방문·현관문·비상구는 **닫음**, 창·발코니창은 **열음**.
  실제 집의 평소 모습에 가깝고, 대부분 아이가 바꾸지 않아도 된다 (D3).

## 3. 공용부와 바깥 출구 (의견 6)

### 3.1 `ground_exit` 를 출구 종류로 넓힌다

지금은 "밖으로 나가는 곳" 하나뿐이다. 실제로는 세 갈래다.

| subKind | 이름 | 뜻 |
|---|---|---|
| `ground_exit` | 1층 밖 | 계단으로 내려가 지상으로 나간다 (기본) |
| `roof_exit` | 옥상 | 아래가 막혔을 때 위로. 옥상 문이 잠겨 있으면 못 쓴다 |
| `basement_exit` | 지하 | 지하 주차장 쪽 출구 |

- 셋 다 `MarkerKind` 이고 그래프의 **목표 노드**가 된다.
- **화재의 기본 원칙은 아래로 나가는 것이다.** 옥상은 "아래가 막혔을 때"에만 옳다.
  규칙 `RULE-F-08`(신규)이 이를 본다 — 주 경로가 옥상으로 가면 지적,
  보조 경로가 옥상이면 지적하지 않는다.
- **지하는 화재 때 옳지 않다.** `RULE-F-09`(신규) — 어느 경로든 지하로 가면 지적한다.
  (침수 확장판에서는 반대로 지하가 금지, 옥상이 권장이 된다. `EXTENSION_RULES` 에 둔다.)
- 규칙을 더했으므로 `content/ruleMessages.json` 에 `reportHeadline`·`praise` 두 문장(easy·normal)과
  `content/guide/rules.json` 의 `ruleFail` 대사를 함께 더한다.

## 4. 시간 (의견 7)

### 4.1 우리집 타이머

두 가지를 나눠 보인다. 둘 다 **연습 모드에서도** 보인다.

| 이름 | 무엇 | 어디 |
|---|---|---|
| **지난 시간** | 게임이 시작하고 흐른 시각(초). 틱 × 프리셋 `tickSeconds` | 게임 상단 |
| **우리집 나가는 시간** | 성공했을 때 걸린 시간. 최고 기록과 함께 저장 | 리포트·저장 파일 |

  넘겨도 지지 않는다. 도전 모드의 게이지는 v1.1 그대로다 (FR-8.2 유지).
- 리포트에는 등수를 만들지 않는다 (FR-10.10). "지난번보다 12초 빨랐어" 같은
  **자기 기록과의 비교**만 쓴다.

## 5. 연출 (의견 8)

### 5.1 시간에 따른 확산을 눈에 보이게

지금은 셀마다 연기 농도를 반투명 회색으로 칠할 뿐이라 "번지고 있다"가 잘 안 읽힌다.

- **불** — 세기에 따라 4단계(그을음 → 붉은 기 → 불꽃 → 다 탐)로 칠을 나눈다.
  불꽃은 SVG 로 그린 작은 혀 모양을 셀마다 하나 놓고, 세기에 따라 크기가 자란다.
- **연기** — 농도를 3단계 등고선처럼 겹쳐 칠해 **번져 나가는 앞머리**가 보이게 한다.
- **문틈** — 닫힌 문 너머로 연기가 스며드는 것을 문 자리에 짧은 띠로 그린다.
- `prefers-reduced-motion` 이면 자라는 연출을 끄고 단계 칠만 남긴다.

## 6. 캐릭터 (의견 10 · 11)

### 6.1 말풍선이 도면을 가리지 않게

지금 말풍선은 도면 위에 떠 있다(`position: absolute; bottom: 16px`). 도면과 겹친다.

**고침**: 말풍선을 도면 **아래 칸**으로 내린다. 도면 영역과 말풍선이 형제가 되어
겹치지 않는다. `.k-center` 의 격자에 줄을 하나 더 둔다.
말풍선이 없을 때는 그 줄이 0 이 되어 도면이 다시 넓어진다.

### 6.2 내 캐릭터 고르기

`UserProfile.playerCharacter` 는 이미 있다(1종 고정). 고를 수 있게 연다.

- 후보 **10종 — 남학생 5 · 여학생 5**. 게임에서 내가 될 아이다. 지도하는 캐릭터
  (일구·영이·웅이)와는 다른 것이다. 그쪽은 말을 거는 쪽이고 이쪽은 내가 움직이는 쪽이다.
- 전부 SVG 로 그린다(CON-5 — 비트맵 없음). 얼굴 뼈대와 칠하는 방식은 하나로 두고
  **머리 모양 · 머리 색 · 피부 톤 · 옷 색 · 소품**으로 가른다. 그래야 열 명을 그려도
  번들이 늘지 않는다.
- 아이가 자기와 닮은 아이를 고를 수 있어야 하므로 피부 톤을 한 가지로 두지 않는다.
- 고르는 자리: 온보딩에 칸을 더하지 않는다 (조작 수 유지). 상단바 「내 캐릭터」에서 고른다.
- 고른 캐릭터가 게임의 플레이어이자 3D 리플레이의 주인공이 된다.

## 7. 소리 (의견 9)

### 7.1 v1.1 §3.7 R8 과의 관계

v1.1 은 "경고음·붉은 점멸을 쓰지 않는다"고 했다. 이유는 **아동 불안**이다.
의견 9의 목적은 다르다 — 아이가 **진짜 감지기 소리를 알아듣게** 하는 것이다.
불안을 만들지 않으면서 그 목적을 이루는 조건을 붙여 허용한다.

| 조건 | 내용 |
|---|---|
| C1 | **끌 수 있다.** 상단바에 소리 켬/끔이 있고, 상태는 저장된다 |
| C2 | 감지기 소리는 **게임이 시작될 때 한 번, 2초 이내**. 계속 울리지 않는다 |
| C3 | **실패를 소리로 알리지 않는다.** 지는 순간에는 소리를 내지 않는다 |
| C4 | 붉은 점멸은 여전히 금지다 |
| C5 | 소리는 **부가 기능**이다. 나지 않아도 모든 기능이 완결된다 (NFR-1) |

### 7.2 구현 — 파일을 싣지 않는다

오프라인 배포본은 4MB 를 넘을 수 없다(NFR-3). 음원 파일을 넣지 않는다.

- **감지기 소리** — Web Audio 로 합성한다. 3.1kHz 근처 구형파를 0.1초씩 세 번(실제
  주거용 감지기의 T-3 패턴), 음량은 -18dBFS 로 낮춘다.
- **음성** — Web Speech API(`speechSynthesis`)로 캐릭터 대사를 읽는다.
  피치를 올려(1.35) 어린이에게 친근한 소리로 만든다. 한국어 음성이 없으면 **조용히 끈다**
  (v1.0 §7.4 의 TTS 방침 그대로). 음성 때문에 진행이 막히는 곳은 없다.
- 자동 재생 제한 때문에 **첫 조작 전에는 소리를 내지 않는다.** AudioContext 는
  이용자가 처음 누른 뒤에 만든다.

## 8. 3D 리플레이 (의견 13)

### 8.1 무엇을 3D 로 하고 무엇을 하지 않는가

```
그리기(2D SVG) ─▶ 대피 게임(2D SVG) ─▶ 결과 리포트 ─▶ [3D 로 다시 보기]
                                                          └ 새 화면. 게임을 대체하지 않는다
```

- **에디터·게임·인쇄는 그대로다.** v1.1 §0.2 의 다섯 가지 근거(인지 부담, 성능, 번들,
  개발 기간, 인쇄 일관성)는 전부 그 세 곳에 걸린 것이었고, 하나도 되돌리지 않는다.
- 3D 는 **리플레이 전용**이다. 이미 끝난 판을 다시 보는 화면이라
  프레임이 떨어져도 학습이 막히지 않는다. 저사양 기기 리스크(v1.0 R5)가 되살아나지 않는다.

### 8.2 FR-11 신규 — 3D 리플레이

#### 8.2.1 시점 3종

| 시점 | 무엇 | 기본 |
|---|---|---|
| **1인칭** (`first`) | 그때 그 눈높이. 낮은 자세면 눈도 내려가고 천장이 보인다 | **기본값** |
| 뒤에서 (`follow`) | 어깨 너머로 따라간다. 내가 어디쯤인지 함께 보인다 | |
| 위에서 (`top`) | 평면도처럼 내려다본다. 불이 어디까지 왔는지 한눈에 본다 | |

1인칭을 기본으로 둔다. **"그때 내가 무엇을 보았나"** 가 이 화면의 목적이기 때문이다.
위에서 보는 것은 이미 2D 게임 화면이 하던 일이라 기본이 될 이유가 없다.

### 8.3 왜 라이브러리를 쓰지 않는가

`CLAUDE.md` §9-12 는 런타임 의존성을 `react`·`react-dom`·`zustand` 로 못 박았고,
NFR-3 은 단일 HTML 4MB 를 정했다. Three.js 는 gzip 150KB 다. 리플레이가 필요로 하는 것은
**상자를 세우고, 반투명한 판을 겹치고, 카메라를 옮기는 것**뿐이라 직접 쓰는 편이 싸다.

`src/ui/replay3d/` 에 둔다.

| 파일 | 하는 일 |
|---|---|
| `geometry.ts` | 평면도 → 정점 배열(바닥·벽·문틀·가구 상자). `core/**` 규칙과 무관한 UI 계층이다 |
| `gl.ts` | WebGL2 최소 감싸개 — 셰이더·버퍼·행렬. 라이브러리를 쓰지 않는다 |
| `smoke.ts` | 연기 판(빌보드) — 셀별 농도를 높이 3층으로 나눠 겹친다 |
| `Replay3D.tsx` | 화면. 재생 제어와 자막 |

### 8.4 그리는 방법

- **벽** — 방 사각형의 둘레에서 벽 선분을 뽑아 높이 2.4m 로 세운다. 개구부 자리는
  문틀만 남기고 잘라 낸다(에디터의 벽 생성과 같은 규칙).
- **연기** — 셀마다 카메라를 향한 판을 세 층(바닥 0.4m·허리 1.2m·천장 2.0m) 놓고
  농도를 알파로 준다. 위층이 먼저 짙어져 **연기가 위에서부터 내려온다**가 보인다.
- **불** — 세기에 따라 색이 오르는 발광 상자 + 위로 흔들리는 판 두 장.
- **빛** — 방향광 하나 + 불에서 나오는 점광 하나. 그림자는 만들지 않는다(비용 대비 효과 없음).
- **해상도** — `devicePixelRatio` 를 그대로 받아 그린다(최대 2). 리플레이는 실시간
  입력이 없으므로 프레임보다 화질을 택한다 (FR-11 의 "해상도 높은").

### 8.5 데이터 — 무엇을 기록해야 하는가

리플레이는 **이미 있는 것으로 만든다**. `PlayLog` 에 프레임 기록을 더한다.

```ts
export interface ReplayFrame {
  tick: number;
  cell: Cell;
  posture: Posture;
  /** 그 틱의 주 위험·부 위험 — 셀당 1바이트(0~255)로 줄여 저장한다 */
  primary: Uint8Array;
  secondary: Uint8Array;
  events: string[];
}
```

- 24×16 = 384셀 × 2 = 768바이트/틱. 300틱이면 230KB. **저장 파일에는 넣지 않는다**
  (메모리에만 두고, 저장·불러오기 대상이 아니다). 새로고침하면 리플레이는 사라진다.
- 대신 `PlayLog` 에는 지금처럼 요약만 남긴다. 저장 포맷(§7.4)은 바뀌지 않는다.

### 8.6 마지막 장면 — 가족이 반긴다

리플레이가 불타는 집에서 끝나면 아이에게 남는 마지막 그림이 불이다. **무사히 나온
판에서는** 마지막에 집 밖 「가족이 만나는 곳」으로 넘어가 가족이 손을 흔들고, 나가는 데
몇 초 걸렸는지를 적는다.

- **성공했을 때만 나온다.** 실패한 판에는 넣지 않는다. 못 나온 아이에게 못 만난 가족을
  보이는 것은 벌이 된다(§9.3 — 실패를 벌하지 않는다).
- 걸린 시간은 적되 **등급도 등수도 붙이지 않는다.** 자기 기록일 뿐이다 (FR-10.10 · §4.1).
- 「가족이 만나는 곳」을 정하지 않았어도 장면은 나온다. 리포트가 따로 짚어 준다.

이 장면이 있어야 §4.1 의 「우리집 나가는 시간」과 인쇄물의 「우리 가족 만나는 곳」이
한 줄로 이어진다 — **그리고, 연습하고, 만난다.**

## 12. 작업 화면의 세 칸

편집할 때 화면 가운데는 **팔레트 | 도면 | 사용법** 세 칸이다.

| 칸 | 폭 | 언제 |
|---|---|---|
| 팔레트 (`.k-palette`) | `--k-pal-w` 200px | 늘 |
| 도면 (`.k-center`) | 남는 자리 | 늘 |
| 사용법 (`.k-howto`) | `--k-howto-w` 268px (접으면 92px) | **편집할 때만** |

게임·리포트에서는 사용법 칸이 사라져 두 칸이 되고 도면이 넓어진다. 사용법 칸은
챗봇이 아니다 — 지금 고른 도구에 맞는 고정 문장을 고르기만 한다(`CLAUDE.md` §9-2).

### 12.1 층 순서

도면 위에 얹는 것은 `svg.stage`(z-index 1) 보다 위여야 한다(`CLAUDE.md` §5).

### 12.2 빛깔 토큰의 자리

`--k-bg`·`--k-line`·`--k-ink` 같은 토큰은 **`:root` 에 둔다.** 덮개(`.k-modal-back`)와
첫 화면(`.k-gate`)은 `.k-app` **밖에** 그려지므로, 토큰을 `.k-app` 에 두면 그것들이
토큰을 받지 못해 테두리가 통째로 사라진다. 폭 토큰(`--k-pal-w`·`--k-howto-w`)만
`.k-app` 에 남긴다.

## 13. 좁은 화면 — 세로 스마트폰

아이가 실제로 쥐는 것은 세로 스마트폰이다. 상단바 단추 열두 개를 그대로 두면 가로로
밀려 아무것도 찾지 못한다. **기준선은 `max-width: 767px`** 하나다.

### 13.1 화면 크기의 층

층이 겹치면 서로를 덮어써서 갈래가 세로로 서고 「그만」이 사라진다. **범위를 서로
겹치지 않게 못 박는다.**

| 층 | 범위 | 배치 |
|---|---|---|
| PC | `min-width: 1024px` | 팔레트 \| 도면 \| 사용법 세 칸 (§12) |
| 태블릿 | `min-width: 768px` and `max-width: 1023px` | 팔레트가 도면 **위**로 올라가 가로 막대 |
| 세로 스마트폰 | `max-width: 767px` | 팔레트가 도면 **아래**로 내려가 가로 띠 (§13.2) |
| 아주 좁음 | `max-width: 479px` | 위에 더해 시트 단추를 두 칸으로 |

태블릿 층에 위쪽 경계(`min-width: 768px`)를 반드시 적는다. 빠뜨리면 스마트폰에서도
태블릿 규칙이 함께 걸린다.

### 13.2 격자 칸은 `minmax(0, 1fr)` 로 적는다

`grid-template-columns: 1fr` 은 `minmax(auto, 1fr)` 이라 최솟값이 안쪽 내용의
min-content 다. 단추가 늘어선 상단바나 블록 여덟 칸이 든 팔레트가 들어 있으면
**칸이 390px 이 아니라 730px 로 벌어지고**, `.k-app` 의 `overflow: hidden` 이 넘친
부분을 잘라 낸다. 도면과 팔레트 오른쪽이 통째로 사라졌던 원인이다.

`.k-app` 과 `.k-work` 의 칸을 `minmax(0, 1fr)` 로 적는다.

### 13.3 무엇을 어디로 옮기는가

| 것 | 넓은 화면 | 좁은 화면 |
|---|---|---|
| 이용 수준 · 게임 방식 · 블록 외형 | 상단바 | **「더보기」 시트** |
| 집 모양 · 처음부터 · 내 캐릭터 · 사용법 · 첫 화면 · 파일 저장 · 불러오기 | 상단바·하단바 | **「더보기」 시트** |
| 되돌리기 · 소리 · 인쇄 · 대피 연습 시작 · 이제 뭘 해야 해? | 상단바·하단바 | 그대로 둔다 |
| 팔레트 | 왼쪽 세로 칸 | **도면 아래 가로 띠** |
| 사용법 칸 | 오른쪽 세로 칸 | 감춘다 — 하단바의 「이제 뭘 해야 해?」와 말풍선이 대신한다 |
| 진행률 · 자동 저장 표시 | 하단바 | 감춘다 |

감추는 것은 `.k-hide-sm`, 좁은 화면에서만 나오는 것은 `.k-only-sm` 이다.
**`.k-hide-sm` 에는 넓은 화면용 규칙을 두지 않는다.** `display` 를 적어 두면 뒤에 오는
그 규칙이 `.k-tb`·`.k-seg` 의 `inline-flex` 를 덮어쓴다.

### 13.4 팔레트 띠

도면이 위, 팔레트가 아래다. 팔레트는 세로 흐름(`flex-column`)이라 「더보기」를 폈을 때
띠가 늘어나고 접으면 줄어든다. **늘어나도 화면의 40%(`40dvh`)를 넘지 않는다** —
「더보기」를 편 채로도 도면이 세로 150px 밑으로 내려가지 않게 잡은 값이다.

| 부분 | 좁은 화면 |
|---|---|
| 도구 (`.k-tools`) | 세 칸 가로 |
| 기본 여덟 칸 (`.k-blocks.k-basic`) | 한 줄로 두고 가로 스크롤 |
| 더보기 (`.k-more-panel`) | **감추지 않는다.** 갈래는 가로 스크롤, 블록은 세 칸씩 세로 스크롤 |
| 무엇을 들고 있는지 (`.k-armed`) | **감추지 않는다.** 띠 맨 위로 올린다 |

`.k-more-panel` 을 감추면 기본 여덟 칸 말고는 아무것도 놓을 수 없게 된다.
`.k-armed` 를 감추면 든 것을 내려놓을 「그만」이 사라진다 — 나가는 길이 보여야 한다는
`CLAUDE.md` §5 에 어긋난다. **둘 다 감추지 않는다.**

게임·리포트에서는 팔레트 자체가 사라져 도면이 화면을 다 쓴다.

도면 위 막대(`.k-canvas-bar`)는 390px 에 다 들어가지 않는다(주·보조 · 길 지우기 ·
체크 셋). 두 줄을 먹느니 한 줄로 두고 가로로 민다. 왼쪽의 주·보조는 늘 보인다.

### 13.5 덮개

모달은 아래에서 올라오는 판이 된다 — 화면 폭을 다 쓰고, 높이는 `88dvh` 까지,
위쪽 두 모서리만 둥글다. 폭은 `100%` 이고 덮개의 안쪽 여백은 0 이다. `100vw` 를 쓰면
여백만큼 삐져나가 문서가 가로로 넓어진다.

### 13.6 지키는 것

- **가로로 넘치지 않는다.** 문서의 `scrollWidth` 만 재면 안 된다 — `.k-app` 이
  `overflow: hidden` 이라 넘친 것이 잘려 나가고 문서는 멀쩡해 보인다. 검증은
  `.k-app`·`.k-top`·`.k-work`·`.k-center`·`.k-palette`·`.k-bottom` 각각의
  `scrollWidth - clientWidth` 를 따로 잰다.
- **도면이 화면 안에 있고 볼 만한 크기다.** 검증이 `svg.k-stage` 의 자리와 크기를 잰다.
- 앱 높이는 `100dvh` 다. 주소창이 오르내려도 하단바가 잘리지 않는다.
- 누르는 것은 좁은 화면에서도 **48×48 이상**이다(`--k-hit`). 좁다고 줄이지 않는다.
- 아주 좁은 화면(`max-width: 479px`)에서는 시트의 단추를 두 칸으로 줄인다.
