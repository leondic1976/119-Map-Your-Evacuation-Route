# 우리집 대피지도 변경 명세 v1.10 — PC 게임형 3D 리플레이

이 문서는 v1.9 이후의 변경 정본이다. 충돌할 때 v1.10이 앞선다.

## 1. 범위와 불변 조건

- 3D는 결과 뒤 리플레이 `src/ui/replay3d/**`에서만 사용한다. 에디터·2D 게임·인쇄는 `PlanSvg`를 유지한다.
- 3D 리플레이는 기록을 관찰하는 화면이며 새 점수·등급·순위·시간제한을 만들지 않는다.
- 이용자가 그린 평면, 문 상태, 위험장, 실제 이동 기록, 선택 캐릭터를 그대로 사용한다.
- 외부 모델·HDRI·이미지 텍스처·웹폰트를 런타임에 받지 않는다. 모든 장식과 표면은 코드와
  런타임 캔버스 텍스처로 만든다.
- 단일 오프라인 HTML 4MB 미만, 외부 참조 0건, WebGL 실패 시 2D 대체를 유지한다.

## 2. 화면 배치

### 2.1 상단 카메라 조작부

- 3D 화면 최상단에 `3D 대피 리플레이`, 현재 시각, `어디서 볼까?`를 한 줄로 표시한다.
- `내 눈으로`, `뒤에서`, `집 전체` 세 시점 단추를 상단에 항상 보인다. 각 누르기 영역은 48px 이상이다.
- 같은 줄에 `위`, `아래`, `왼쪽`, `오른쪽`, `정면` 단추를 둔다. 방향은 Lucide 벡터 아이콘과
  한글 접근성 이름을 함께 사용한다.
- 닫기 단추도 상단 오른쪽에 두고 `Esc`를 유지한다.
- 1024px PC에서 가로 스크롤이나 캔버스 겹침 없이 모두 보여야 한다.

### 2.2 장면과 보조 패널

- 상단 조작부는 별도 격자 행을 차지한다. WebGL 캔버스 위에 덮어 눌림을 막지 않는다.
- 오른쪽 유리판은 재생·처음·한 칸·빠르기·겹 켜기·화질처럼 보조 설정만 맡는다.
- 현재 시각과 행동 자막, `마우스로 끌어 둘러봐` 안내는 장면 아래쪽 게임 HUD에 표시한다.
- 시간 이동 막대는 화면 맨 아래 48px을 유지한다.

## 3. 카메라

### 3.1 공통 상태

- 카메라 상태는 `{ yaw, pitch, zoom }` 한 벌이다.
- 시점을 바꾸면 `yaw=0`, `pitch=0`, `zoom=1`로 초기화한다.
- 마우스 왼쪽 단추로 장면을 끌면 `yaw`와 `pitch`가 함께 바뀐다. 휠은 `zoom`을 바꾼다.
- `pitch`는 바닥과 천장을 뒤집어 통과하지 않도록 제한한다.
- 상단 방향 단추와 키보드 방향키는 마우스와 같은 상태를 바꾼다. 입력·시간 범위 요소가
  포커스인 때는 전역 방향키를 가로채지 않는다.

### 3.2 시점별 적용

- `내 눈으로`: 아이 눈높이 위치는 대피 기록을 따르고, 진행 방향에 `yaw`를 더한 뒤 `pitch`로
  위아래를 본다. 서 있을 때와 몸을 낮췄을 때 눈높이가 다르다.
- `뒤에서`: 진행 방향 뒤쪽 카메라가 아이를 따라가되 `yaw`로 아이 둘레를 돌고 `pitch`로 높이를
  바꾼다. 캐릭터를 화면 중심 가까이에 유지한다.
- `집 전체`: 집 중심을 공전하며 `yaw`, `pitch`, `zoom`을 모두 사용한다. 벽은 허리 높이에서 잘라
  바닥과 대피 길을 가리지 않는다.

## 4. 렌더링 화질

화질은 `ultra`, `high`, `low` 세 내부 값이며 화면에는 `고급`, `높음`, `가벼움`으로 표시한다.

| 값 | DPR | 그림자 맵 | 후처리 | 절차 무늬 | 장식·실내등 |
|---|---|---:|---|---|---|
| `ultra` | 1.35~2.25 | 4096 | AO+블룸 | 512 | 전체 |
| `high` | 1~1.75 | 2048 | AO+약한 블룸 | 256 | 주요 |
| `low` | 1~1.15 | 없음 | 없음 | 없음 | 최소 |

- 8코어 이상이며 움직임 줄이기 설정이 아니면 `ultra`, 5~7코어면 `high`, 4코어 이하면 `low`로 시작한다.
- 준비 시간 뒤 평균 24fps 미만이면 `ultra → high`, `high → low`로 한 번 자동 하향한다.
- 렌더러는 sRGB 출력, 영화형 톤 매핑, 고화질 단계의 부드러운 PCF 그림자, 고성능 GPU 선호를 사용한다.
- 하향해도 카메라·길·표지·위험장·자막·캐릭터 기능을 제거하지 않는다.

## 5. 장면 디테일

### 5.1 실내

- 방 용도별로 나무 바닥, 정사각 타일, 잔점 무늬 바닥 중 하나를 절차형 텍스처로 얹는다.
- 침실·거실에는 용도에 맞는 러그를 두되 대피 길보다 아래에 그려 길을 가리지 않는다.
- 벽 있는 방에는 낮은 몰딩을 둘러 바닥과 벽의 접점을 읽히게 한다.
- `내 눈으로`에는 천장을 그린다. `뒤에서`는 캐릭터 전신과 주변 길이 보이도록 카메라를 충분히
  떨어뜨리고 천장과 벽 윗부분을 자르는 게임식 컷어웨이를 쓴다. `집 전체`도 천장을 숨긴다.
- 각 주요 공간 중앙에 천장등 장식과 그림자를 만들지 않는 실내 채움광을 둔다. 저화질에서는 끈다.
- 금속·유리·천·나무는 거칠기와 반사값을 달리한다. 고비용 물리 재질은 일부 장식에만 쓴다.

### 5.2 실외

- 집 둘레에 보도 블록, 진입로, 잔디 띠를 겹쳐 집이 실제 땅 위에 놓인 깊이를 만든다.
- 고화질에서는 다층 잎 나무, 관목, 가로등을 결정론적으로 배치한다.
- 장식은 집 외곽 안이나 출구 바로 앞을 막지 않는다.

### 5.3 빛과 위험장

- 하늘빛, 태양광, 실내 채움광, 불빛을 분리하고 AO로 접촉 그림자를 보강한다.
- 불은 입체 불꽃 코어와 외곽 불꽃으로 보이고, 연기는 위에서 먼저 짙어지는 층을 유지한다.
- 불빛·화질 전환·표지는 붉게 점멸하지 않는다.

## 6. 접근성과 조작

- 모든 상단·오른쪽 패널 단추는 최소 48×48이다.
- 현재 시점은 색뿐 아니라 `aria-pressed`, 아이콘, 문구로 구분한다.
- 방향 단추에는 `data-look-direction`, 시점 단추에는 `data-view`를 둬 자동 조작과 도움 기능이
  같은 요소를 찾게 한다.
- 카메라 상태는 장면 요소의 `data-camera-yaw`, `data-camera-pitch`, `data-camera-zoom`으로 노출해
  실제 조작 결과를 브라우저 검증에서 읽는다.
- `prefers-reduced-motion`이면 카메라 보간은 유지하되 장식 애니메이션과 경로 흐름을 줄인다.

## 7. 검증과 완료 기준

- `npm test`: 화질 3단 설정과 자동 하향 순서가 순수 값으로 검증된다.
- `npm run smoke`: 상단 시점 3개, 방향/정면 5개, 마우스 yaw/pitch, 방향 단추, 방향키,
  원위치, 화질 3단, WebGL/2D 대체, 닫기와 `Esc`를 실제 Chromium에서 조작한다.
- `npm run shots`: 1024×768과 1440×900에서 1인칭·뒤에서·집 전체를 찍고 상단 UI 잘림,
  장면 겹침, 바닥·천장·장식·캐릭터를 눈으로 확인한다.
- 실제 발화 문장은 바꾸지 않는다. `VOICE-SCRIPT.md`와 ElevenLabs MP3는 이번 작업 대상이 아니다.
