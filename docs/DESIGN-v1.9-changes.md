# 우리집 대피지도 v1.9 변경 명세

## 1. 목적

상자와 잔여공간으로 만든 평면에서 공용공간을 여러 `RoomBlock`으로 나눈 뒤 경계마다
`open_passage`를 그려 지우던 방식은 벽이 군데군데 끊긴 것처럼 보인다. 어린이가 실제 집의
형태를 이해하기도 어렵다. v1.9부터는 **집 외곽을 먼저 그리고, 실제로 문을 닫을 수 있는
독립실만 내부 벽으로 구획하며, 남은 면적은 하나로 이어진 공용 바닥**으로 표현한다.

이 문서는 v1.8의 상자·잔여공간 생성 규칙 가운데 화면 표현과 저장 투영 규칙을 대체한다.
대피 그래프와 기존 저장 자료의 호환성은 유지한다.

## 2. 외곽 우선 생성 순서

```text
shell(shape)
  -> placeClosedRooms(침실·욕실·선택한 피난전실·알파룸·닫힌 주방)
  -> publicFloor = shell - closedRooms
  -> reserveOpenKitchenZone()
  -> decomposePublicFloorForCompatibility()
  -> classifyZones(거실·복도·현관·트인 주방)
  -> connectZonesForGraphWithoutDrawingWalls()
  -> autoDoorsForClosedRooms()
  -> frontDoorAndBedroomWindows()
  -> validateShellAndProjection()
```

- `FloorPlan.shell.cells`에는 회전 가능한 집 외곽 칸을 저장한다.
- 침실과 욕실은 기본 독립실이다. 피난전실과 알파룸은 미리보기에서 선택하면 독립실로 놓는다.
- 닫힌 주방을 선택하면 독립실로 놓고, 트인 주방은 공용 바닥 위의 용도 구역으로 놓는다.
- 독립실은 `wallMode: 'closed'`, 거실·복도·현관·트인 주방은 `wallMode: 'zone'`이다.
- 직사각형 여러 개로 나눈 공용 바닥은 저장·그래프 호환을 위한 내부 표현일 뿐 실제 벽이 아니다.

## 3. 2D 표시 규칙

1. `shell.cells`의 바깥 경계만 굵고 연속된 외벽으로 그린다.
2. `closed` 방은 채움과 네 면의 내부 벽을 그린다.
3. `zone`은 채움색과 이름만 그리고 직사각형 둘레선을 그리지 않는다.
4. 공용 구역 사이 `open_passage`는 통행 그래프에는 남기되 `hideInPlan: true`로 저장하여
   흰색 지우개 그림을 그리지 않는다.
5. 현관문과 창문은 마지막에 외곽벽 위에 그려 정상적인 개구부로 보이게 한다.
6. 선택한 구역은 벽과 혼동되지 않는 점선 강조 테두리를 잠시 보여 준다.

기존 평면처럼 `shell`이나 `wallMode`가 없는 자료는 종전 방식으로 그려 저장 호환성을 지킨다.

## 4. 3D 표시 규칙

- 외부 칸과 맞닿은 경계에는 외벽을 세운다.
- `closed`와 다른 공간의 경계에는 내부 벽을 세운다.
- 두 `zone` 사이에는 벽을 세우지 않는다.
- 문·창문과 통행 상태는 기존 개구부 자료를 그대로 사용한다.
- 따라서 2D에서 하나로 이어진 공용 바닥은 1인칭 3D에서도 막힘없이 이어져야 한다.

## 5. 어린이용 선택 규칙

`방 상자로 쉽게 만들기`의 미리보기에는 다음 선택을 한 화면에 둔다.

- 주방: 문 없는 트인 주방 / 문 있는 주방 / 잘 모르겠어
- 추가 독립실: 피난전실 / 알파룸
- 방향: 그대로 / 오른쪽 / 거꾸로 / 왼쪽

욕실은 기본으로 자동 배치한다. 추가 독립실은 누르면 즉시 미리보기에 나타나며, 공간이 부족한
후보는 남은 공용 바닥이 끊기지 않는 가장 가까운 작은 크기로 배치한다. 아이가 추가 도구를
배우지 않아도 결과를 얻을 수 있어야 한다.

## 6. 검증

- 테두리 8종, 침실 1~4개, 주방 2종, 방 위치 조합을 전부 생성한다.
- 생성된 방의 합집합과 `shell.cells`가 정확히 같고 겹침이나 누락이 없는지 검사한다.
- 생성 평면의 공용 구역은 모두 `zone`, 독립실은 모두 `closed`인지 검사한다.
- 공용 구역 사이 연결은 `open_passage`이면서 `hideInPlan: true`인지 검사한다.
- 현관문에서 모든 침실까지 그래프 경로가 있는지 검사한다.
- 브라우저에서 외곽벽이 하나로 이어지고 공용부에 흰색 벽 지움 자국이 없는지 검사한다.
- 스크린샷으로 미리보기와 실제 캔버스의 외곽·내부 벽·라벨을 눈으로 확인한다.

## 7. MP3를 직접 다시 듣는 방법

- 말풍선에는 `목소리 다시 듣기` 단추를 둔다. 자동 재생이 브라우저 정책이나 빠른 화면 전환으로
  끊겨도 어린이가 한 번 눌러 현재 대사를 다시 들을 수 있어야 한다.
- 소리가 꺼진 상태에서는 같은 단추를 `목소리 켜고 듣기`로 표시한다. 단추 한 번으로 소리를 켜고
  현재 대사의 MP3를 재생한다.
- 상단의 `소리 켜짐` 단추로 소리를 다시 켤 때도 가장 최근 말풍선 MP3를 해당 클릭 안에서
  곧바로 다시 재생한다. 자동 재생 효과에만 기대지 않는다.
- 검증은 MP3 요청과 해독 성공에 그치지 않고, 실제 `HTMLMediaElement.play()` 호출·Promise 성공·
  `playing` 이벤트까지 확인한다.

## 8. 캔버스 블록을 다시 옮기고 방 크기 바꾸기

- `내 자리`, `만나는 곳`, 가구·안전설비처럼 한 칸짜리 블록은 놓은 뒤에도 고르기 도구로
  직접 끌어 다른 칸에 옮길 수 있어야 한다.
- 같은 칸에 침대와 `내 자리`처럼 여러 블록이 겹치면 화면에서 실제로 누른 `data-block`을
  우선한다. 좌표만으로 찾을 때는 가장 나중에 그린 위쪽 블록을 우선한다.
- 방은 방 안을 끌어 이동하고, 선택 뒤 나타나는 여덟 방향 손잡이를 끌어 크기를 바꾼다.
- 포인터 이동 중 보이는 미리보기와 실제 반영에 같은 최종 좌표를 쓴다. React 화면 갱신이
  늦어도 포인터를 놓는 순간의 이동값을 잃지 않도록 드래그 참조에 최종값을 따로 보존한다.
- 한 칸짜리 블록 이동, 방 이동, 방 크기 변경, 여러 블록 함께 이동을 실제 Chromium 드래그로
  검사하고 새로고침 뒤에도 바뀐 좌표가 유지되는지 확인한다.

## 9. 템플릿과 직접 그리기 일곱 단계

첫 화면은 `템플릿으로 빠르게 시작`과 `직접 그리기` 두 갈래만 보여 준다. 템플릿은 완성된
예시를 불러와 바로 고칠 수 있게 하고, 직접 그리기는 구조와 가구를 한꺼번에 결정하지 않도록
다음 순서를 고정된 길잡이로 제공한다.

```text
1 집 모양
  → 2 공간 나누기(침실·욕실·빈 독립실 / 거실·주방·현관·베란다)
  → 3 독립실 크기·위치
  → 4 가구 놓기·방과 열린 공간 이름 짓기
  → 5 내 방·내 위치
  → 6 같이 모이는 곳
  → 7 소화기·감지기 등 안전 위치 확인
```

- 직접 그리기 시작 평면에는 가구·안전설비·위험원·표시를 넣지 않고 외곽·공간·문만 남긴다.
  침대 때문에 방을 고르는 것이 아니라 실제 벽과 공간부터 맞추게 한다.
- `공간 나누기`에서는 닫힌 실을 침실·욕실·피난전실·알파룸으로, 벽 없는 바닥을 거실·트인
  주방·현관·복도·베란다로 지정하고 필요한 실과 문·창을 더한다.
- `독립실 크기·위치`에서는 닫힌 방만 끌어 옮기거나 여덟 손잡이로 크기를 바꾼다. 남은 열린
  바닥은 매번 외곽 안을 빈틈없이 다시 채운다.
- `가구·이름`에서 처음으로 침대·책상·소파·화재 위험원을 보여 주고, 선택한 독립실과 열린
  공간의 이름을 직접 고칠 수 있게 한다.
- `내 방·내 위치`, 집 밖 `같이 모이는 곳`을 차례로 정한 뒤, 마지막에 소화기·감지기·기타
  안전설비의 실제 위치를 확인한다.
- 안전 위치를 모르는 어린이에게 임의로 놓게 하지 않고 “부모님이나 선생님과 함께 찾아보자”는
  안내와 나중에 보완할 길을 제공한다.
- 단계마다 왼쪽 팔레트와 캔버스 위 안내는 지금 필요한 선택만 먼저 보여 주되, 완성 뒤 일반
  편집 화면에서는 모든 항목을 다시 고칠 수 있다.
- 두 갈래 시작, 일곱 단계 전환, 독립실/공용 구역 용도와 이름 변경, 가구가 구조 선택보다 늦게
  나타나는지, 안전 확인 뒤 일반 편집으로 가는지 Chromium으로 검사한다.

## 10. 사이트 접속 절차와 어린이 기본정보

```text
교육 목적이 있는 배경 소개 화면
  → 브라우저가 PC 작업 해상도(가로 1024px 이상)인지 판단
  → 학교 · 학년 · 반 · 이름 입력
  → 우리집 대피지도 그리기(템플릿 / 직접 그리기)
```

- 모바일·태블릿 폭이면 기본정보를 받지 않고 PC에서 다시 열라는 안내만 보여 준다.
- 기본정보 화면은 학교, 1~6학년, 반, 이름을 어린이가 순서대로 입력할 수 있는 큰 입력칸과
  `우리집 대피지도 그리기` 단추를 둔다.
- 어린이 정보는 네트워크로 전송하지 않고 현재 브라우저의 대피지도 저장 자료에만 포함한다는
  짧고 쉬운 고지를 입력칸 바로 옆에 보여 준다.
- 학교·반·이름의 앞뒤 빈칸을 정리하고 빈 값은 다음 단계로 보내지 않는다. 학년은 1~6만 받는다.
- Chromium에서 소개 전에는 입력 화면이 없고, 소개 뒤 PC에서만 기본정보 화면이 나타나며,
  네 항목을 채운 뒤 집 그리기 두 갈래 화면으로 이어지는지 검사한다.

## 11. 캠페인 대시보드

상단 `사용법` 바로 오른쪽에 `대시보드`를 두고, 현재 PC 브라우저에서 만든 대피지도 활동을
학교·학년·반별로 살펴보는 캠페인 화면을 연다.

- 소방서: 참여 학교와 안전 항목 확인, 학교: 학년·반별 진행 확인, 학부모: 가족 지도와 실제
  소화기·만나는 장소 확인이라는 세 협력 역할을 첫 화면에 설명한다.
- 목록은 학교·학년·반·이름, 수정 시각, 지도 완성도, 안전설비·경로·대피연습 상태를 보여 준다.
- 점수는 경쟁 순위가 아니라 `안전 완성도`로 표시한다. 구조 20, 안전 위치 25, 대피경로 30,
  연습 25의 고정 기준을 공개하고 이름순 또는 최근 수정순으로만 정렬한다.
- 학교·학년·반 필터와 전체/진행 중/완료 요약을 제공한다.
- 현재 배포는 서버가 없는 GitHub Pages이므로 이 브라우저의 자료만 집계한다. 기관 간 중앙 공동
  관리는 보호자 동의, 기관 계정과 역할 권한, 전송 암호화, 보관·삭제 기한, 감사 기록을 갖춘
  별도 서버가 마련된 뒤에만 연결하며 화면에서 현재 한계를 오해 없이 고지한다.
- 실제 Chromium에서 단추 위치, 필터, 현재 학생 행, 완성도 계산, 닫기와 Esc를 검사한다.
