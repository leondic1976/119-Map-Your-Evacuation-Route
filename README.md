# 우리집 대피지도

초등학생이 **우리 집을 블록으로 만들고**, 대피할 길을 그리고, **불이 난 집에서 직접 빠져나와 보는**
재난안전 학습 프로그램이다. 끝나면 잘한 점과 고칠 점을 정리해 주고, 그때 그 장면을 **3D 로 다시 보여 주고**,
집에 붙일 **A4 대피지도 한 장**으로 뽑아 준다.

한 아이가 자기 집 하나를 위해 쓰는 **개인용 도구**다. 학교에서도 집에서도 PC 에 내려받아 설치해 쓰고,
한 번 받아 두면 **인터넷이 없어도** 돈다. 서버·로그인·전송이 없다.

| 받는 곳 | 주소 |
|---|---|
| 웹에서 바로 열기 (V2 로 간다, [`V2/`](V2/README.md)) | <https://leondic1976.github.io/119-Map-Your-Evacuation-Route/> |
| PC에 설치하기 (세 갈래 안내) | <https://leondic1976.github.io/119-Map-Your-Evacuation-Route/download/> |

> 이 앱의 확산 해석은 소방 교육자료에서 통용되는 눈높이 수치를 채택한 **교육용 근사 모델**이며,
> 성능위주설계(FDS 등) 해석을 대체하지 않는다. 또한 **법정 피난안내도를 대체하지 않는다.**

## 웹에서 바로 쓰기, 그리고 PC에 설치하는 세 가지 길

설치하지 않고 **웹 주소를 바로 열어도** 전부 된다. 한 번 연 PC 는 다음부터 인터넷 없이도 열린다(설계서 v1.20 §2).
설치는 바탕화면 아이콘이 필요하거나 처음부터 인터넷이 없는 PC 를 위한 것이다.
어느 것이든 인터넷 없이 돌고, 그린 지도는 그 PC 안에만 저장된다.

| 길 | 이렇게 | 어울리는 때 |
|---|---|---|
| **브라우저에 설치** | 사이트를 연 Chrome·Edge·Whale 의 주소창 설치 아이콘을 누르거나, 안내 페이지의 「지금 설치하기」를 누른다. 바탕화면과 시작 메뉴에 아이콘이 생긴다. 캐릭터 목소리 176개는 설치 뒤 뒤에서 조용히 받아 둔다 | 인터넷이 한 번은 되는 PC. 가장 쉽다 |
| **오프라인 꾸러미** | `home-escape-map-offline.zip` 을 받아 압축을 풀고 `우리집 대피지도/home-escape-map.html` 을 두 번 누른다. 목소리 폴더 `voice/` 는 옆에 그대로 둔다 | 인터넷이 없는 교실, USB 로 옮기는 PC |
| **윈도우 설치 파일** | 안내 페이지의 `HomeEscapeMap-Setup-<판>.exe`(설치판) 또는 `HomeEscapeMap-Portable-<판>.exe`(무설치판). 처음 실행 때 SmartScreen 창이 뜨면 「추가 정보 → 실행」 | 브라우저 없이 바로 켜는 PC 프로그램이 필요할 때 |

설치 파일은 코드 서명이 없다. 서명 비용을 내지 않은 무료 교육 프로그램이라 경고 창이 한 번 뜬다.

### 새 판 (설계서 v2.0 §7)

| 형태 | 새 판 받기 |
|---|---|
| 웹 · 브라우저 설치 | 열 때 서비스 워커가 새 판을 받아 두고 「새 판이 준비됐어 · 다시 열기」를 띄운다. 설정 메뉴의 「새 판 확인」으로 손수 확인한다 |
| 윈도우 설치판 | 켤 때 `download/latest.json` 으로 판을 견준다. 더 새것이면 묻고, 받아서 sha256 을 맞춘 뒤 조용히 덮어쓰고 다시 연다. F5 로 손수 확인한다 |
| 무설치판 · 꾸러미 | 새 판이 있으면 받는 곳을 열어 준다. 새 파일로 바꿔 쓰면 된다 |

판 번호는 `package.json` 한 곳이고, 바뀐 것은 `CHANGELOG.md` 에 적는다.

### 다른 웹 서버에 올리기

- **꾸러미 폴더를 그대로** — `우리집 대피지도/` 폴더를 통째로 서버의 어느 경로에 올리고 `home-escape-map.html` 주소를 열면 된다.
  모든 경로가 상대 경로이고 바깥에서 받아오는 것이 없다. 서비스 워커는 등록하지 않는다.
- **브라우저 설치까지 쓰려면** — `BASE_PATH=/올릴/경로 npm run build` 로 만든 `out/` 을 올린다. 매니페스트·서비스 워커·설치 안내의 주소가 그 경로로 들어간다.

## 선생님·보호자께

- **필요한 PC** — Chrome·Edge·Whale 최신 2개 판, 화면 너비 1024px 이상(1280×800 권장). 소리는 없어도 다 된다.
  1024px 미만에서는 본 기능을 실행하지 않고 PC 이용 안내만 보인다.
- **자료가 가는 곳** — 이름표·집 도면·연습 기록은 그 PC 의 브라우저(또는 프로그램) 안에만 저장된다.
  이 앱은 인터넷에 어떤 요청도 보내지 않는다. `npm test` 가 코드의 바깥 호출 0건을 매번 확인한다.
- **다른 PC 로 옮기기** — 화면 아래 「파일 저장」으로 `.json` 을 내려받고 다른 PC 에서 「불러오기」로 연다.
- **새 판** — 브라우저 설치판은 사이트가 바뀌면 화면 아래 「새 판이 준비됐어 · 다시 열기」 알림이 뜬다.
  그리던 도중에 저절로 바뀌지 않는다.
- **지우기** — 브라우저 설치판은 앱 창 메뉴의 제거, 윈도우 설치판은 「앱 및 기능」, 꾸러미는 폴더 삭제.

## 개발

```bash
npm install
npm run dev          # http://localhost:3000
```

| 명령 | 내용 |
|---|---|
| `npm run build` | 정적 내보내기 → `out/` + 마감(`tools/pack.ts`: 매니페스트·서비스 워커·꾸러미 복사) |
| `npm run build:standalone` | 오프라인 배포본 → `dist/home-escape-map.html` + `dist/voice/` + `dist/home-escape-map-offline.zip` |
| `npm run typecheck` | TypeScript strict 타입 검사 |
| `npm test` | 연산 로직 · 배포 전 점검 100항목 (화면 없이 실행) |
| `npm run smoke` | Chromium 실조작 40시나리오 (`npm run build:standalone && npm run build` 뒤) |
| `npm run validate` | 콘텐츠 검증 (개발 모드 · `--strict` 는 배포 모드) |
| `npm run verify` | 위 전부를 순서대로 (타입 검사 → 콘텐츠 → 배포본 → 빌드 → 로직·배포 전 점검 → 브라우저). 산출물 검사가 있어 로직 검증은 빌드 뒤에 돈다 |
| `npm run desktop:build` | 윈도우 설치판·무설치판 → `release/` (`--dir` 은 폴더만) |
| `npm run desktop:check` | Electron 껍데기를 실제로 띄워 소개 → 이름표 → 편집 · 바깥 요청 0건 확인 (`-- --packaged` 는 빌드본 exe 로) |
| `npm run icons` | 앱 아이콘 PNG 를 Chromium 으로 다시 그린다 (`public/icons/`, `desktop/icon.png`) |
| `npm run shots` | PC 화면 캡처 (`SHOT_VIEWPORT=1440x900`) |

smoke 를 처음 실행하기 전에 `npx playwright install chromium` 이 한 번 필요하다.
내려받기가 막힌 곳에서는 `SMOKE_CHROMIUM` 에 크로미움 실행 파일 경로를 준다.

### 배포 순서

`main` 푸시가 `.github/workflows/deploy.yml` 을 돌린다. 검증을 통과해야만 GitHub Pages 로 배포된다.

```
오프라인 배포본(+ZIP) → 검증용 내보내기(+마감) → 브라우저 검증 → 배포용 내보내기(BASE_PATH, +마감) → Pages 업로드
```

`tools/standalone.ts` 는 `out/` 을 **오프라인 모드로 다시 내보내므로** 배포용 내보내기보다 반드시 앞에 온다.
`tools/pack.ts` 는 `next build` 뒤에 기준 경로를 넣어 `manifest.webmanifest`·`sw.js` 를 만들고 `dist/` 의 ZIP 을
`out/download/` 로 옮긴다. 선캐시는 앱 껍데기뿐이고 MP3 는 활성화 뒤 배경에서 받는다. ZIP 은 캐시하지 않는다.

윈도우 설치 파일은 별도 워크플로 `.github/workflows/desktop.yml`(windows 러너)이 만들어 Release `desktop` 태그에
덮어쓰기로 올린다. 저장소가 비공개라 Release 주소는 공개 링크가 아니므로, `deploy.yml` 이 그 산출물을 받아
`dist/desktop/` 에 두고 `tools/pack.ts` 가 Pages 의 `download/` 에 함께 싣는다. 안내 페이지는 같은 사이트 안의
그 파일을 가리키고, 아직 없으면 준비 중이라고 말한다. 로컬에서는 `npm run build:standalone && npm run desktop:build` 다.

### 오프라인 HTML 의 함정

HTML 에서 `<link>` 를 지우는 것만으로는 부족하다. Next.js 는 같은 참조를 스트리밍 페이로드에도 실어 보내고,
수화 과정에서 React 가 그것을 다시 넣기 때문이다. 그래서 빌드 자체를 오프라인 모드로 다시 돌려 웹폰트와 매니페스트를
아예 렌더하지 않게 하고, 페이로드에 남은 스타일시트 경로는 내용이 담긴 data URL 로 바꾼다.
`npm run smoke` 가 `file://` 에서 네트워크 요청 0건·오류 0건을 실제로 확인한다.

의존 방향은 한 줄이다. `core` → 아무것도, `store` → `core`·`content`·`platform`,
`ui` → `store`·`core`·`content`·`platform`, `app` → `ui`. 거꾸로 가는 화살표는 없다.
`npm test` 가 이 경계와 함께 **소방서-학교 플랫폼의 잔재 0건**(대시보드·학교 자동 시연·학교/반 입력)을 지킨다.

설계서는 `docs/DESIGN-v1.0.md` 와 변경 명세 `docs/DESIGN-v1.1-changes.md`부터
`docs/DESIGN-v1.20-changes.md`, 그리고 대개편 `docs/DESIGN-v2.0-changes.md`까지다. 어긋나면 뒤 문서가 이긴다.
받은 지시와 그 처리 상태는 `docs/REQUESTS.md` 에 모아 둔다. 폐기한 캠페인 대시보드 문서는 `docs/archive/` 에 있다.

### 핵심 알고리즘

**위험장** — 매 프레임 물리 연산 대신 칸마다 연료·감쇠를 두고 단계적으로 번지게 한다.
문·창이 열렸는지 닫혔는지, 방화문인지에 따라 감쇠가 달라지고, 연기가 불보다 빠르다.
엔진 자체는 재난 이름을 모르고 `content/hazards/*.json` 프리셋이 속도와 연료를 준다.

**발화점 추첨** — 매번 다른 자리에 불이 나되, 시작 즉시 이길 수 없는 판은 내지 않는다.
후보마다 앞으로 몇 틱을 미리 돌려 목표까지 살아 갈 길이 남는지 보고 고른다.
`npm test` 가 시작 평면 전종 × seed 100 회로 이것을 확인한다.

**경로 판정** — 평면을 그래프로 바꾸고(방·개구부·출구), 통행 가능성 표에 따라 이어
목표 집합까지 닿는지 본다. 주 경로와 보조 경로는 서로 다른 `ScenarioKey` 로 각각 평가된다.

## 접근성

포커스 표시 2px 아웃라인, `aria-pressed`/`aria-label` 부여, 색상 외 형태(아이콘·선 두께·점선)로도
상태를 구분한다. `npm run smoke` 가 편집·게임·리포트·설치 안내의 **모든 글자와 모든 단추를 전수로** 재어 확인한다.

| 항목 | 지키는 값 |
|---|---|
| 누르는 것의 최소 크기 | **48×48** — `--k-hit` 한 곳에서 정한다 |
| 본문 대비 | 4.5:1 (큰 글자 3:1) · 자동 검증 |
| 키보드만으로 | 된다 — Tab 으로 도면에 들어가 방향키로 칸을 옮기고 Enter 로 누른다 |
| 움직임 줄이기 | `prefers-reduced-motion` 존중 |
| 붉은 점멸 | 쓰지 않는다 |

## 호환성

Chrome / Edge / Whale 최신 2개 판. PC 1024px 이상(1280×800 권장). 윈도우 설치 파일은 윈도우 10·11 64비트.
