# 우리집 대피지도 변경 명세 v1.19

작성일: 2026-10-30

대상: 조작 편의 · 도면 중심 배치 · 3D 리플레이 사실감

우선순위: 이 문서가 v1.18(제품화)보다 뒤의 결정이며 충돌하면 v1.19가 이긴다. v1.4 §1.1(3D 기술 스택)·§2(장면)·
v1.10 §4(화질)·§5(장면 디테일)·v1.17 §3(캔버스 중심 화면)은 이 문서로 **보완**한다. 폐기하는 조항은 없다.

요청 대장 #91.

## 1. 문제

1. **조작** — 도면 칸이 작을 때 문·창·가구를 정확히 누르기 어려운데 도면을 키울 방법이 없다. 3D 리플레이는
   휠이 없는 노트북에서 가까이 볼 수 없고, 오른쪽 설정 패널이 장면의 오른쪽을 늘 가린다.
2. **배치** — 큰 모니터나 창 최대화에서 도면이 세로에 묶여 가로가 남고, 어떤 틀은 창을 따라 늘어난다.
   이용자는 **창을 키우면 가운데 도면만 커지는** 화면을 원한다.
3. **3D** — 정점 색 한 벌의 벽·바닥, 스티커 같은 불·연기, 두 색 하늘이라 사실감이 모자란다.

## 2. 조작 편의

### 2.1 도면 확대·축소 (신규 FR-7.12)

- 도면 막대(경로 탭 줄)에 `축소` · `확대` · `맞춤` 단추를 둔다. 누르는 크기는 48×48 이상이다.
- 단계는 맞춤 기준 **1 → 1.25 → 1.5 → 2 → 2.5 → 3배**다. `맞춤`은 1배로 돌아온다. 계산은 `core/zoom.ts`의
  `nextZoom()`이 하고 `tools/logic-tests.ts`가 순서를 잰다.
- **Ctrl+휠**은 도면을 확대·축소한다(브라우저 확대를 가로챈다). 입력란 밖에서 `+`·`-`·`0` 키도 같은 일을 한다.
- 확대하면 도면 칸에 스크롤이 생긴다. 휠로 위아래, Shift+휠로 좌우로 움직인다. 1배에서는 스크롤이 없다.
- 확대 배율은 저장하지 않는다. 게임·리포트로 넘어가도 유지되고 새로 열면 1배다. 인쇄·3D 는 영향이 없다.
- 도면의 좌표 변환은 SVG `getScreenCTM`이라 배율이 바뀌어도 누르는 자리가 어긋나지 않는다.

### 2.2 전체 화면 (신규 FR-7.13)

- 상단바 오른쪽에 `전체 화면` 단추(`data-coach="kids-fullscreen"`)를 둔다. 전체 화면이면 `창으로`가 된다.
- 브라우저 전체 화면 API 는 `platform/host.ts`의 `Host.screen`에서만 부른다. UI 는 `host().screen`만 쓴다.
  데스크톱 앱의 F11(v1.18 §5.3)은 그대로다.
- 브라우저가 전체 화면을 막은 곳(iframe·일부 환경)에서는 단추를 숨긴다.

### 2.3 3D 리플레이 조작

- 「보는 방향」 줄에 `가까이`·`멀리` 단추(`data-look-zoom="in"|"out"`)를 더한다. 휠·`+`·`-` 키와 같은 값을 바꾼다.
- 오른쪽 「화면 설정」 패널은 `접기`로 접고 `설정` 단추(`data-coach="kids-replay-panel-toggle"`)로 편다.
  접으면 장면이 끝까지 보인다. 처음에는 펴져 있다.
- 장면을 두 번 누르면 시점이 정면으로 돌아온다(`정면` 단추와 같다).
- 48×48, `Esc`, 키보드 방향키, `aria-pressed` 는 v1.10 §6 그대로다.

## 3. 도면 중심 배치 (v1.17 §3 보완)

- 틀의 치수는 **CSS px 고정**이다 — 상단 52 · 하단 52 · 팔레트 300 · 사용법 268(접으면 60) · 도면 막대 54 ·
  만들기 띠 104 · 해설 칸 92. `vw`·`vh`·`%` 로 틀을 늘리지 않는다.
- 남는 공간은 **전부** 도면 칸(`.k-canvas-wrap`)이 가진다. 도면은 칸 안에서 비율을 지키며 가장 크게(맞춤) 놓이고
  가로·세로 가운데에 온다. 맞춤 크기는 CSS 컨테이너 단위(`cqw`·`cqh`)로 계산해 측정 코드 없이 창을 따라간다.
- 확대 배율은 맞춤 크기에 곱한다. 1배를 넘으면 칸이 스크롤된다(§2.1).
- 1024×768 → 1920×1080 → 2560×1440 에서 틀의 치수는 같고 도면만 커진다. `npm run smoke`가 1280 과 1920 을
  견줘 상단·하단·팔레트·접힌 사용법 폭이 같고 도면이 1.3배 이상 커졌는지 잰다.
- 3D 리플레이도 같다. 상단 조작부 72 · 시간 막대 48 은 고정이고 장면이 나머지 전부를 차지한다. 패널은 장면 위에
  떠 있고 접힌다(§2.3).

## 4. 3D 사실감 (v1.4 §1·§2 · v1.10 §4·§5 보완)

### 4.1 기술

런타임 의존성 **목록**(v1.4 §1.1)은 그대로 두고 **판만 올린다** — three r186 · `@react-three/fiber` 9.8 ·
`@react-three/drei` 10.7 · `@react-three/postprocessing` 3.2. WebGPU 렌더러(`three/webgpu`·TSL)는 **넣지 않는다**:
단일 HTML 4MB 예산을 1MB 넘게 쓰고, 교실 PC 의 오래된 GPU 에서 어차피 WebGL 로 내려간다. 사실감은 아래 기법으로 낸다.

| 기법 | 내용 | 고급 | 높음 | 가벼움 |
|---|---|---|---|---|
| 환경광(IBL) | 하늘·지평선·땅 세 색의 돔과 작은 태양 원반을 PMREM 으로 한 번 구워 `scene.environment` 로 쓴다. 금속·유리·바닥에 하늘빛과 태양 하이라이트가 비친다. 산란 하늘을 그대로 구우면 벽이 통째로 하늘색으로 물들어 값을 아는 돔을 쓴다 | 1.0 | 1.0 | 0.9 |
| 물리 하늘 | three `Sky`(Preetham 산란) + 태양 위치를 방향광과 같이 둔다. 멀리는 지수 안개로 흐려진다 | O | O | 두 색 하늘 |
| 부드러운 그림자 | PCSS(drei `SoftShadows`)로 멀수록 번지는 그림자, 집 밑 접촉 그림자 | PCSS 4096 | PCF 2048 | 없음 |
| PBR 절차 재질 | 바닥은 색·법선·거칠기 맵(나무결·타일 줄눈·테라조), 벽은 석고 미세 법선, 문은 나무결, 유리는 물리 재질(클리어코트·반사) | 1024 | 512 | 정점색 |
| 입체 불 | 인스턴스 빌보드에 fbm 노이즈 불꽃 셰이더. HDR 발광이 블룸으로 번지고 불씨가 오른다 | 4옥타브·불씨 | 3옥타브 | 2옥타브 |
| 입체 연기 | 노이즈 연기 셰이더 인스턴스. 위에서부터 짙어지는 세 층, 천천히 흐른다 | O | O | O |
| 후처리 | MSAA 4x · N8AO · 블룸 · 비네트 · 집 전체 시점의 피사계 심도(미니어처 느낌) | 전부 | AO·블룸·MSAA | 없음 |
| 톤 매핑 | AgX · 노출 1.1 · sRGB 출력 | O | O | O |

지키는 것 — **외부 요청 0건**(HDRI·글꼴·모델·이미지 없음, 전부 코드), **4MB**, **점멸 금지**(불꽃은 연속으로
흔들리는 것이고 `prefers-reduced-motion` 에서는 멈춘다), **WebGL 없으면 2D**, **화질 세 단과 자동 하향**,
검증이 읽는 `data-*` 속성과 `data-coach` 이름.

`geometry.ts` 는 면마다 평면 UV 를 함께 낸다(STRIDE 9 → 11). 유리·가구는 따로 낸다 — 벽과 재질이 다르다.
불·연기 색은 시간에 따라 **밝기를 흔들지 않는다**. 모양만 흐른다.

재질은 옥타브마다 격자값을 미리 굽는 값 노이즈로 만들어 1024² 한 장이 100ms 대이고, 한 벌(10종)은
**한 장씩 프레임을 양보하며** 굽는다(`makeSurfacesAsync`). 다 구워질 때까지는 정점 색으로 보인다 —
3D 가 열리는 순간 화면이 멎지 않는다. 블룸 문턱은 1 위다: 환경광을 받은 보통 면은 번지지 않고
불꽃·빛나는 길·천장등처럼 1 을 넘는 것만 번진다. three r186 은 `PCFSoftShadowMap` 이 없어 PCF 를 쓰고
부드러움은 고급 화질의 PCSS 가 맡는다.

### 4.2 바깥

잔디(노이즈·흙 섞임·바람 결), 보도 블록 줄눈, 아스팔트 거칠기와 차선, 나무(줄기 굽힘·잎 뭉치 변위·잎 색 차이),
관목, 가로등, 이웃집(창·기와색 지붕·굴뚝), 낮은 울타리. 전부 결정론적 배치(같은 seed)다.

### 4.3 안

천장등·걸레받이는 그대로, 러그는 직조 거칠기, 문짝은 나무결에 손잡이. 창은 유리가 하늘을 비친다.

## 5. 검증

- `npm test`
  - `nextZoom()` 단계와 되돌림, `settingsFor()` 3단(새 항목 `softShadows`·`dof`·`msaa`·`sky`·`fireOctaves`·`embers`)과 하향 순서.
  - 3D 사실감 기법(PMREM 환경광·물리 하늘·PCSS·물리 유리·법선 맵·후처리·노이즈 불꽃)이 소스에 있고 바깥 자산 흔적이 없다.
  - 전체 화면 API(`requestFullscreen`·`exitFullscreen`·`fullscreenElement`)는 `src/platform/` 에만 있다.
  - `geometry.ts` STRIDE 가 11 이고 `buildHouse` 가 벽·가구·유리를 나눠 낸다.
  - 기존: three 는 `ui/replay3d/` 안, `Environment preset`·`Text` 금지, 4MB, 의존성 목록.
- `npm run smoke`
  - 확대·축소·맞춤 단추와 Ctrl+휠로 도면 크기가 바뀌고 스크롤이 생기며 맞춤에서 돌아온다.
  - 전체 화면 단추가 있고 누르면 오류가 없다(헤드리스는 전체 화면을 못 하므로 상태는 안 본다).
  - 1280×800 과 1920×1080 에서 틀 치수가 같고 도면만 1.3배 이상 커진다.
  - 3D: `가까이`·`멀리` 로 `data-camera-zoom` 이 바뀌고, 패널 접기·펴기, 기존 시점·방향·화질·닫기.
- `npm run shots`: 1920×1080 편집 화면과 3D 세 시점.
- 음성: 실제 발화 문장을 바꾸지 않는다. `VOICE-SCRIPT.md`·MP3 176개 그대로.
