# 우리집 대피지도 v1.9 변경 명세

## 1. 목적

상자와 잔여공간으로 만든 평면에서 공용공간을 여러 `RoomBlock`으로 나눈 뒤 경계마다
`open_passage`를 그려 지우던 방식은 벽이 군데군데 끊긴 것처럼 보인다. 어린이가 실제 집의
형태를 이해하기도 어렵다. v1.9부터는 **집 외곽을 먼저 그리고, 실제로 문을 닫을 수 있는
독립실만 내부 벽으로 구획하며, 남은 면적은 하나로 이어진 공용 바닥**으로 표현한다.

이 문서는 v1.8의 상자·잔여공간 생성 규칙 가운데 화면 표현과 저장 투영 규칙을 대체한다.
대피 그래프와 기존 저장 자료의 호환성은 유지한다.

## 2. 외곽 우선 생성 순서

```text
shell(shape)
  -> placeClosedRooms(침실·욕실·선택한 피난전실·알파룸·닫힌 주방)
  -> publicFloor = shell - closedRooms
  -> reserveOpenKitchenZone()
  -> decomposePublicFloorForCompatibility()
  -> classifyZones(거실·복도·현관·트인 주방)
  -> connectZonesForGraphWithoutDrawingWalls()
  -> autoDoorsForClosedRooms()
  -> frontDoorAndBedroomWindows()
  -> validateShellAndProjection()
```

- `FloorPlan.shell.cells`에는 회전 가능한 집 외곽 칸을 저장한다.
- 침실과 욕실은 기본 독립실이다. 피난전실과 알파룸은 미리보기에서 선택하면 독립실로 놓는다.
- 닫힌 주방을 선택하면 독립실로 놓고, 트인 주방은 공용 바닥 위의 용도 구역으로 놓는다.
- 독립실은 `wallMode: 'closed'`, 거실·복도·현관·트인 주방은 `wallMode: 'zone'`이다.
- 직사각형 여러 개로 나눈 공용 바닥은 저장·그래프 호환을 위한 내부 표현일 뿐 실제 벽이 아니다.

## 3. 2D 표시 규칙

1. `shell.cells`의 바깥 경계만 굵고 연속된 외벽으로 그린다.
2. `closed` 방은 채움과 네 면의 내부 벽을 그린다.
3. `zone`은 채움색과 이름만 그리고 직사각형 둘레선을 그리지 않는다.
4. 공용 구역 사이 `open_passage`는 통행 그래프에는 남기되 `hideInPlan: true`로 저장하여
   흰색 지우개 그림을 그리지 않는다.
5. 현관문과 창문은 마지막에 외곽벽 위에 그려 정상적인 개구부로 보이게 한다.
6. 선택한 구역은 벽과 혼동되지 않는 점선 강조 테두리를 잠시 보여 준다.

기존 평면처럼 `shell`이나 `wallMode`가 없는 자료는 종전 방식으로 그려 저장 호환성을 지킨다.

## 4. 3D 표시 규칙

- 외부 칸과 맞닿은 경계에는 외벽을 세운다.
- `closed`와 다른 공간의 경계에는 내부 벽을 세운다.
- 두 `zone` 사이에는 벽을 세우지 않는다.
- 문·창문과 통행 상태는 기존 개구부 자료를 그대로 사용한다.
- 따라서 2D에서 하나로 이어진 공용 바닥은 1인칭 3D에서도 막힘없이 이어져야 한다.

## 5. 어린이용 선택 규칙

`방 상자로 쉽게 만들기`의 미리보기에는 다음 선택을 한 화면에 둔다.

- 주방: 문 없는 트인 주방 / 문 있는 주방 / 잘 모르겠어
- 추가 독립실: 피난전실 / 알파룸
- 방향: 그대로 / 오른쪽 / 거꾸로 / 왼쪽

욕실은 기본으로 자동 배치한다. 추가 독립실은 누르면 즉시 미리보기에 나타나며, 공간이 부족한
후보는 남은 공용 바닥이 끊기지 않는 가장 가까운 작은 크기로 배치한다. 아이가 추가 도구를
배우지 않아도 결과를 얻을 수 있어야 한다.

## 6. 검증

- 테두리 8종, 침실 1~4개, 주방 2종, 방 위치 조합을 전부 생성한다.
- 생성된 방의 합집합과 `shell.cells`가 정확히 같고 겹침이나 누락이 없는지 검사한다.
- 생성 평면의 공용 구역은 모두 `zone`, 독립실은 모두 `closed`인지 검사한다.
- 공용 구역 사이 연결은 `open_passage`이면서 `hideInPlan: true`인지 검사한다.
- 현관문에서 모든 침실까지 그래프 경로가 있는지 검사한다.
- 브라우저에서 외곽벽이 하나로 이어지고 공용부에 흰색 벽 지움 자국이 없는지 검사한다.
- 스크린샷으로 미리보기와 실제 캔버스의 외곽·내부 벽·라벨을 눈으로 확인한다.

## 7. MP3를 직접 다시 듣는 방법

- 말풍선에는 `목소리 다시 듣기` 단추를 둔다. 자동 재생이 브라우저 정책이나 빠른 화면 전환으로
  끊겨도 어린이가 한 번 눌러 현재 대사를 다시 들을 수 있어야 한다.
- 소리가 꺼진 상태에서는 같은 단추를 `목소리 켜고 듣기`로 표시한다. 단추 한 번으로 소리를 켜고
  현재 대사의 MP3를 재생한다.
- 상단의 `소리 켜짐` 단추로 소리를 다시 켤 때도 가장 최근 말풍선 MP3를 해당 클릭 안에서
  곧바로 다시 재생한다. 자동 재생 효과에만 기대지 않는다.
- 검증은 MP3 요청과 해독 성공에 그치지 않고, 실제 `HTMLMediaElement.play()` 호출·Promise 성공·
  `playing` 이벤트까지 확인한다.

## 8. 캔버스 블록을 다시 옮기고 방 크기 바꾸기

- `내 자리`, `만나는 곳`, 가구·안전설비처럼 한 칸짜리 블록은 놓은 뒤에도 고르기 도구로
  직접 끌어 다른 칸에 옮길 수 있어야 한다.
- 같은 칸에 침대와 `내 자리`처럼 여러 블록이 겹치면 화면에서 실제로 누른 `data-block`을
  우선한다. 좌표만으로 찾을 때는 가장 나중에 그린 위쪽 블록을 우선한다.
- 방은 방 안을 끌어 이동하고, 선택 뒤 나타나는 여덟 방향 손잡이를 끌어 크기를 바꾼다.
- 포인터 이동 중 보이는 미리보기와 실제 반영에 같은 최종 좌표를 쓴다. React 화면 갱신이
  늦어도 포인터를 놓는 순간의 이동값을 잃지 않도록 드래그 참조에 최종값을 따로 보존한다.
- 한 칸짜리 블록 이동, 방 이동, 방 크기 변경, 여러 블록 함께 이동을 실제 Chromium 드래그로
  검사하고 새로고침 뒤에도 바뀐 좌표가 유지되는지 확인한다.

## 9. 템플릿과 직접 그리기 일곱 단계

첫 화면은 `템플릿으로 빠르게 시작`과 `직접 그리기` 두 갈래만 보여 준다. 템플릿은 완성된
예시를 불러와 바로 고칠 수 있게 하고, 직접 그리기는 구조와 가구를 한꺼번에 결정하지 않도록
다음 순서를 고정된 길잡이로 제공한다.

```text
1 집 모양
  → 2 공간 나누기(침실·욕실·빈 독립실 / 거실·주방·현관·베란다)
  → 3 독립실 크기·위치
  → 4 가구 놓기·방과 열린 공간 이름 짓기
  → 5 내 방·내 위치
  → 6 같이 모이는 곳
  → 7 소화기·감지기 등 안전 위치 확인
```

- 직접 그리기 시작 평면에는 가구·안전설비·위험원·표시를 넣지 않고 외곽·공간·문만 남긴다.
  침대 때문에 방을 고르는 것이 아니라 실제 벽과 공간부터 맞추게 한다.
- `공간 나누기`에서는 닫힌 실을 침실·욕실·피난전실·알파룸으로, 벽 없는 바닥을 거실·트인
  주방·현관·복도·베란다로 지정하고 필요한 실과 문·창을 더한다.
- `독립실 크기·위치`에서는 닫힌 방만 끌어 옮기거나 여덟 손잡이로 크기를 바꾼다. 남은 열린
  바닥은 매번 외곽 안을 빈틈없이 다시 채운다.
- `가구·이름`에서 처음으로 침대·책상·소파·화재 위험원을 보여 주고, 선택한 독립실과 열린
  공간의 이름을 직접 고칠 수 있게 한다.
- `내 방·내 위치`, 집 밖 `같이 모이는 곳`을 차례로 정한 뒤, 마지막에 소화기·감지기·기타
  안전설비의 실제 위치를 확인한다.
- 안전 위치를 모르는 어린이에게 임의로 놓게 하지 않고 “부모님이나 선생님과 함께 찾아보자”는
  안내와 나중에 보완할 길을 제공한다.
- 단계마다 왼쪽 팔레트와 캔버스 위 안내는 지금 필요한 선택만 먼저 보여 주되, 완성 뒤 일반
  편집 화면에서는 모든 항목을 다시 고칠 수 있다.
- 두 갈래 시작, 일곱 단계 전환, 독립실/공용 구역 용도와 이름 변경, 가구가 구조 선택보다 늦게
  나타나는지, 안전 확인 뒤 일반 편집으로 가는지 Chromium으로 검사한다.

## 10. 사이트 접속 절차와 어린이 기본정보

```text
교육 목적이 있는 배경 소개 화면
  → 브라우저가 PC 작업 해상도(가로 1024px 이상)인지 판단
  → 학교 · 학년 · 반 · 이름 입력
  → 우리집 대피지도 그리기(템플릿 / 직접 그리기)
```

- 모바일·태블릿 폭이면 기본정보를 받지 않고 PC에서 다시 열라는 안내만 보여 준다.
- 기본정보 화면은 학교, 1~6학년, 반, 이름을 어린이가 순서대로 입력할 수 있는 큰 입력칸과
  `우리집 대피지도 그리기` 단추를 둔다.
- 어린이 정보는 네트워크로 전송하지 않고 현재 브라우저의 대피지도 저장 자료에만 포함한다는
  짧고 쉬운 고지를 입력칸 바로 옆에 보여 준다.
- 학교·반·이름의 앞뒤 빈칸을 정리하고 빈 값은 다음 단계로 보내지 않는다. 학년은 1~6만 받는다.
- Chromium에서 소개 전에는 입력 화면이 없고, 소개 뒤 PC에서만 기본정보 화면이 나타나며,
  네 항목을 채운 뒤 집 그리기 두 갈래 화면으로 이어지는지 검사한다.

## 11. 캠페인 대시보드

상단 `사용법` 바로 오른쪽에 `대시보드`를 두고, 현재 PC 브라우저에서 만든 대피지도 활동을
학교·학년·반별로 살펴보는 캠페인 화면을 연다.

- 소방서: 참여 학교와 안전 항목 확인, 학교: 학년·반별 진행 확인, 학부모: 가족 지도와 실제
  소화기·만나는 장소 확인이라는 세 협력 역할을 첫 화면에 설명한다.
- 목록은 학교·학년·반·이름, 수정 시각, 지도 완성도, 안전설비·경로·대피연습 상태를 보여 준다.
- 점수는 경쟁 순위가 아니라 `안전 완성도`로 표시한다. 구조 20, 안전 위치 25, 대피경로 30,
  연습 25의 고정 기준을 공개하고 이름순 또는 최근 수정순으로만 정렬한다.
- 학교·학년·반 필터와 전체/진행 중/완료 요약을 제공한다.
- 현재 배포는 서버가 없는 GitHub Pages이므로 이 브라우저의 자료만 집계한다. 기관 간 중앙 공동
  관리는 보호자 동의, 기관 계정과 역할 권한, 전송 암호화, 보관·삭제 기한, 감사 기록을 갖춘
  별도 서버가 마련된 뒤에만 연결하며 화면에서 현재 한계를 오해 없이 고지한다.
- 실제 Chromium에서 단추 위치, 필터, 현재 학생 행, 완성도 계산, 닫기와 Esc를 검사한다.

## 12. `inst.md` 기준 도면 편집 전면 개편

기존 v1.9 §9의 일곱 단계 순서를 다음 최종 순서로 대체한다. 내부 `Step` 이름은 기존 저장 자료와
테스트 호환을 위해 유지하되, 화면 번호와 다음 단계 전환은 이 순서를 따른다.

```text
1 준비된 집 모양 선택 / 격자 외곽선 직접 그리기
  → 2 방·욕실·현관·옷방·기타실 + 여닫이/미닫이 문·창 배치
  → 3 독립실 위치·크기 + 문·창 폭 조정
  → 4 소파·옷장·침대·싱크대·냉장고·TV·세탁기·건조기 배치
  → 5 실제 소화기 위치 확인·배치
  → 6 내 방 선택·내 위치 배치
  → 7 가족이 모이는 곳 배치
```

### 집 외곽 입력

- 첫 화면에는 `준비된 집 모양 고르기`와 `외곽선을 직접 그리기` 두 선택만 크게 보여 준다.
- 준비된 모양은 8종 외곽을 제공하고 가구가 없는 외곽·공용 바닥부터 시작한다.
- 직접 그리기는 24×16 격자에서 꼭짓점을 차례로 눌러 수평/수직 벽선을 긋는다. 되돌리기·처음부터·
  외곽 완성 단추를 제공하고, 마지막 선은 가능한 한 직각으로 자동 연결한다.
- 자기 교차, 폭/높이 4칸 미만, 지나치게 작은 면적, 끊어진 바닥은 완료하지 않고 고칠 곳을 말한다.
- 완성된 다각형 안쪽 칸을 `shell.cells`로 바꾸고, 처음에는 벽 없는 공용 바닥 한 덩어리만 만든다.

### 실·문·창과 크기

- 2단계에서 침실·욕실·현관·옷방·기타실을 놓는다. 닫힌 실은 내부 벽을 만들고, 현관을 열린
  구역으로 놓는 선택도 유지한다. 방이 하나도 없는 초기 외곽에도 팔레트 클릭→도면 클릭으로 놓인다.
- 방문은 `여닫이문/미닫이문`, 창은 `여닫이창/미닫이창`을 명확히 구분한다.
- 3단계에서 닫힌 실을 끌거나 8방향 손잡이로 조정하고, 선택한 문·창의 폭을 1/2/3칸으로 바꾼다.
- 넓은 문·창은 한 앵커가 차지하는 연속 경계 칸으로 저장한다. 충돌 판정, 경로 그래프, 2D·3D 표시가
  같은 폭을 사용한다. 외곽이나 방 경계를 벗어나면 적용하지 않는다.
- 남는 공간은 벽 없는 공용 바닥으로 즉시 다시 채워 흰색 벽 지움 흔적이 생기지 않게 한다.

### 가구·안전·위치

- 가구는 4단계 전에는 노출하지 않는다. 기존 가구에 세탁기와 건조기를 추가한다.
- 소화기는 5단계에 단독으로 확인하며 “실제 위치를 부모님이나 선생님과 함께 찾아보자”고 안내한다.
- 6단계에서 내 방을 먼저 고르고 내 위치를 놓는다. 7단계에서 집 밖 가족 집결지를 놓으면 길잡이를
  마치고 일반 편집으로 넘어간다.
- 모든 표시와 가구는 놓은 뒤 다시 선택·이동할 수 있다. 단계가 끝난 뒤 일반 편집에서는 모든 도구를
  다시 사용할 수 있다.

## 13. 독립 캠페인 대시보드 사이트

v1.9 §11의 편집기 내부 모달은 폐기하고 `/dashboard/` 독립 페이지로 대체한다. 세부 근거와 단계는
`RESEARCH-campaign-dashboard.md`, `PLAN-campaign-dashboard.md`를 따른다.

- 관리 탐색 계층은 `시도 → 시군구 → 읍면동 → 학교 → 학년 → 반`이다.
- 한 필터가 바뀌면 그 아래 선택은 첫 유효값 또는 `전체`로 초기화한다.
- 같은 필터 결과를 요약 카드, 안전 준비 진행률, 최근 흐름, 학생 활동 표가 공유한다.
- 첫 화면은 학생 친화적 배경 삽화와 캠페인 목적을 보여 주고, 역할별 오늘 할 일과 교실/가정 활동을
  함께 제공한다.
- 학생 총점 순위와 학교 순위를 만들지 않는다. `지도 완성·소화기 확인·두 대피경로·대피연습`을
  완료 상태와 도움이 필요한 항목으로만 집계한다.
- 현재 정적 배포판은 가상 체험 자료와 현재 브라우저 기록만 표시하며 둘을 항상 구분한다. 기관 로그인,
  보호자 동의, 권한, 서버가 없는 상태를 중앙 공동관리라고 표현하지 않는다.
- 편집기 상단 `대시보드`는 모달이 아니라 base path가 적용된 독립 페이지 링크다.
- PC 1024px 이상만 지원하고, 키보드 포커스·표 제목·상태 문자·48px 조작 영역을 제공한다.
- `/dashboard/` 직접 접근/새로고침, 6단계 종속 필터, 검색·상태 조합, 빈 결과, 로컬 자료 병합,
  1024/1280/1440/1920 시각 상태를 Chromium으로 검사한다.

## 14. 욕실·현관·발코니 빠른 추가

`실·문·창` 2단계에서 왼쪽 팔레트를 찾아보지 않아도 자주 필요한 세 공간을 바로 배치할 수 있게 한다.

- 단계 안내 오른쪽에 `욕실`, `현관`, `발코니` 전용 큰 단추를 항상 표시한다. v1.9 §15 이후에는
  `트인 주방`도 같은 빠른 추가 영역에 표시하며, 누르면 해당 공간이
  선택되었다는 상태와 `이제 도면의 빈 곳을 누르세요` 안내를 함께 보여 준다.
- 욕실과 현관은 기본적으로 벽 있는 독립실로 배치한다. 발코니도 먼저 크기 조정이 가능한 독립 공간으로
  놓되, 거실과 이어져 벽이 없는 집은 남은 열린 바닥을 고른 뒤 기존 `베란다` 용도 단추로 바꿀 수 있다.
- 한 번 배치하면 도구 선택을 자동 해제해 어린이가 같은 공간을 실수로 여러 번 놓지 않게 한다. v1.9
  §15 이후에는 같은 2단계에서 다른 독립실과 똑같이 위치를 옮기거나 크기를 바꿀 수 있다.
- 세 단추는 PC 1024px에서도 가로 스크롤 없이 핵심 진행 단추를 가리지 않고, 각각 최소 48px 높이,
  키보드 포커스, `aria-pressed` 상태를 제공한다.
- 화면 전용 조작 문구만 추가하므로 실제 발화 정본과 MP3는 변경하지 않는다.
- Chromium 실조작으로 전용 단추 노출, 각 단추의 선택 상태, 빈 칸 클릭 배치, 실제 `roomKind`,
  한 번 배치 뒤 선택 해제, 같은 단계에서 위치·크기 조정을 검사한다.

## 15. 배치·크기 통합과 주방 영역 지정

### 여섯 단계

어린이가 방을 놓은 뒤 다음 화면으로 이동해야만 크기를 고칠 수 있었던 흐름을 폐기하고 다음 여섯
단계로 줄인다.

```text
1 집 모양
  → 2 실·문·창·크기(배치·이동·크기 조정·문/창 폭)
  → 3 가구 배치
  → 4 소화기
  → 5 내 방·위치
  → 6 모이는 곳
```

- 2단계에서 독립실을 놓은 직후 선택 도구로 끌어 옮기고 여덟 방향 손잡이로 크기를 바꾼다.
- 같은 단계에서 문·창 길이를 조정한다. §16 이후 여닫이는 1·2·3칸, 미닫이는 1~6칸 증감 단추를
  사용하며 별도 `크기 조정` 화면은 없다.
- 내부 `structure` 단계 식별자는 예전 안내 규칙과 자료 호환을 위해 남기되 새 화면 흐름에서는
  진입하지 않는다.
- 단계 막대, 앞/다음 전환, 팔레트, README, 화면 캡처와 Chromium 시나리오는 모두 여섯 단계와
  같은 순서를 사용한다.

### 주방 두 가지

주방은 집마다 벽의 성격이 다르므로 한 가지 방 블록으로 처리하지 않는다.

- 2단계 빠른 추가 영역에 `트인 주방(부엌)`을 둔다. 단추를 누른 뒤 남은 바닥에서 한 번 누르면 4×4칸,
  끌어서 네모를 만들면 그 크기만 `kitchen + wallMode: zone`으로 지정한다.
- 트인 주방과 거실·복도 사이에는 벽이나 문을 그리지 않는다. 내부적으로는 숨은 `open_passage`를
  만들어 통행 그래프, 위험 확산, 2D와 3D가 모두 같은 열린 경계를 사용한다.
- 이미 트인 주방이 있을 때 다시 범위를 지정하면 이전 주방 영역은 거실 바닥으로 되돌리고 새 범위로
  교체한다. 따라서 별도 손잡이 없이도 같은 2단계에서 주방 위치와 크기를 다시 그릴 수 있다.
- 벽과 문으로 나뉜 독립형 주방은 왼쪽 팔레트의 `주방(부엌)`을 놓는다. 다른 독립실처럼 즉시 이동·크기
  조정을 하고 실제 경계에 여닫이문 또는 미닫이문을 붙인다.
- 트인 주방 범위는 집 외곽 안이며 독립실과 겹치지 않는 2×2칸 이상만 허용한다. 조건을 벗어나면
  기존 주방을 건드리지 않고 고칠 위치를 안내한다.
- 화면 조작 문구만 보강하고 캐릭터 실제 발화 정본은 바꾸지 않으므로 이번 작업에서 ElevenLabs
  MP3를 다시 만들지 않는다.

### 검증

- 순수 로직에서 트인 주방 지정, 이전 범위 교체, 잔여 거실 보존, 외곽/독립실 침범 거부, 숨은 열린
  통로 생성을 검사한다.
- Chromium에서 여섯 단계 노출, 2단계 안에서 독립실 이동·손잡이 크기 변경·문/창 폭 변경,
  트인 주방 클릭/드래그 배치, 독립 주방 팔레트 유지, 다음 단계를 누르면 바로 가구로 가는지 검사한다.

## 16. 미닫이 길이·주방 명칭·선택 삭제

### 미닫이문과 미닫이창 길이

- 미닫이문 또는 미닫이창을 고르면 기존 숫자 폭 단추 대신 `줄이기`, 현재 길이, `늘리기`를 한 줄에
  보여 준다. 배치와 방 크기를 다루는 같은 2단계 안에서 조절하며 별도 화면으로 이동하지 않는다.
- 길이는 1칸부터 6칸까지 한 칸씩 바꾼다. 늘어난 모든 칸이 같은 곧은 방 경계 또는 외벽에 있고 다른
  문·창과 겹치지 않을 때만 적용한다. 불가능하면 저장값을 바꾸지 않고 더 짧게 하거나 시작 위치를
  바꾸라고 알려 준다.
- 2D 선택 영역·그림, 클릭 판정, 통행 그래프, 위험 확산, 인쇄와 3D 문짝이 모두 같은 `span`을 쓴다.
  예전 저장자료에 길이가 없으면 1칸으로 읽는다.
- 여닫이문·여닫이창은 기존 1·2·3칸 직접 선택을 유지한다. 미닫이 종류는 증감 조작을 우선 제공해
  어린이가 `길이를 늘리고 줄인다`는 결과를 단추 이름만 보고 이해할 수 있게 한다.

### 주방 표기와 트인 형태

- 어린이용·일반용 명칭을 모두 `주방(부엌)`으로 통일한다. 열린 형태는 `트인 주방(부엌)`, 실제 벽과
  문으로 나뉜 예외 형태는 `벽 있는 주방(부엌)`이라고 표시한다.
- 기본 빠른 추가의 `트인 주방(부엌)`은 남은 바닥에서 끌어 범위를 지정하고 거실·복도와의 경계에
  벽이나 문을 만들지 않는다. 벽 있는 형태는 왼쪽 팔레트 항목의 설명으로 구분한다.

### 선택한 요소 삭제

- 편집 중 도면에서 방·열린 공간·문·창·가구·안전설비·위치 표시를 선택하면 상단 조정 영역의
  첫 조작으로 `삭제하기` 단추를 표시한다. 접근성 이름은 `선택한 것 삭제하기` 또는 `공간 용도
  삭제하기`로 구체화하고, 최소 48px 누르기 영역과 명확한 포커스 상태를 제공한다. 1024px PC에서도
  도움말보다 선택 조작을 우선 표시해 가로 스크롤 없이 바로 누를 수 있어야 한다.
- 기존 `Delete`와 `Backspace` 키도 같은 `removeBlock` 동작을 사용한다. 단추와 키보드가 서로 다른
  삭제 규칙을 갖지 않는다.
- 독립실을 삭제하면 그 안의 가구·표시를 함께 지우고 외곽 안 남은 바닥을 다시 채운다. 주방·복도·
  베란다처럼 벽 없는 용도 구역을 삭제하면 집 바닥을 없애지 않고 일반 거실 바닥으로 되돌린다.
- 삭제 뒤 선택을 해제하며 실행 취소로 복구할 수 있다. 화면 전용 조작 문구만 바꾸므로 캐릭터 실제
  발화와 ElevenLabs MP3는 변경하지 않는다.

### 검증

- 순수 로직에서 미닫이문·미닫이창 1~6칸 증감, 경계 이탈·다른 개구부 충돌 거부, 열린 주방 용도
  삭제 뒤 거실 복원을 검사한다.
- Chromium에서 미닫이 길이의 줄이기/늘리기 단추, 화면 삭제 단추와 Delete 키의 동일 결과,
  `주방(부엌)`·`트인 주방(부엌)` 노출, PC 1024·1440px 배치를 검사한다.
