# 집 구조 입력 개선안 — 「상자 + 잔여공간」 모델

- 작성일: 2026-08-30
- 대상 문서: 「어린이가 자기 집 구조를 쉽게 만드는 방법과 알고리즘 연구보고서」(2026-08-30)
- 성격: 원 보고서를 대체하지 않고 5·6·7·8·10·11·13장을 수정·보완한다.

---

## 1. 검토 결론

### 유지할 것

- 예시 평면을 늘리는 대신 범용 조작으로 자기 집에 도달하게 한다는 방향
- 공간과 경계의 분리, 폭을 가진 문, 여닫이·미닫이 구분
- 결정론적 제약 해결기, 로컬 처리, 어린이 UX 원칙, 검증 순서

### 빠진 전제

> 집에서 어린이가 "그릴 수 있는" 것은 벽으로 둘러싸인 방뿐이다.
> 거실·복도·주방·식당은 그린 것이 아니라 방을 놓고 **남은 자리**다.

원 보고서는 거실·주방·복도를 침실과 같은 `SpaceRegion`으로 두고 어린이가 직접 칠하게 한다(6.4). 이 구조에서는

1. 어린이가 거실의 모양(대개 L자·꺾인 형)을 직접 그려야 한다. 이것이 집 그리기에서 가장 어려운 작업이다.
2. 거실과 주방 사이 경계를 `wall / open / virtual` 중 하나로 골라야 한다. 실제로는 경계 자체가 없다.
3. 추천 알고리즘이 거실까지 영역 성장으로 만들어야 한다. 탐색 공간이 불필요하게 커진다.

### 개선 원칙

**어린이는 상자(닫힌 구획)만 놓는다. 남은 공간은 자동으로 하나의 공용 영역이 되고, 거기에 이름표만 붙인다.**

이 원칙 하나로 거실 모양 그리기, 경계 종류 선택, 주방 문 강요 문제가 동시에 사라진다.

## 2. 구획을 이름이 아니라 성격으로 분류

어린이는 이름 스티커를 고르지만, 성격(벽으로 닫혔는가, 어디에 붙는가)은 스티커에 딸려 온다.

| 성격 | 뜻 | 해당 구획 | 문 기본값 |
|---|---|---|---|
| **A. 닫힌 상자** | 벽과 문으로 둘러싸임 | 침실, 욕실, 화장실, 드레스룸·화장대실, 다용도실, 창고, 서재, 대피공간, 닫힌 주방 | 자동 1개 |
| **B. 반열린 상자** | 한 면 이상이 벽 없이 트임 | 알파룸, 식당 nook, 확장한 발코니 | 문 없음, 트인 면 |
| **C. 잔여 공용부** | 상자 놓고 남은 자리 | 거실, 개방형 주방, 식당, 복도, 현관 앞 | 문 없음, 이름표만 |
| **D. 바깥 부속** | 외곽선 바깥에 붙음 | 발코니·베란다(비확장), 테라스, 마당 | 발코니창(창문형 문) |
| **E. 수직 연결** | 층을 잇는다 | 계단, 다락 사다리, 하향식 피난구 | 상하 연결 |
| **F. 집 밖 공용부** | 현관문 바깥 | 복도, 계단실, 피난전실·부속실, 승강기 홀 | 원 보고서 `common` 레이어 |

- 같은 이름이 두 성격일 수 있다. 주방은 "문이 있어?"에 따라 A 또는 C, 발코니는 "거실이랑 이어져 있어?"에 따라 B 또는 D.
- 이름을 모르는 공간은 "문이 있어?"만 묻고 A/B로 두며 이름은 `기타 1`.

## 3. 새 입력 흐름 (빼기 방식)

| 단계 | 어린이가 하는 일 | 자동으로 되는 일 | 건너뛰기 |
|---|---|---|---|
| 1. 집 테두리 | 네모·긴 네모·ㄱ·ㄴ 중 고르거나 칸을 칠함 | 외곽 경계 생성 | 불가 |
| 2. 현관문 | 테두리 위 한 점을 탭 | 현관 라벨(1~2칸) 자동, 잔여공간 전체가 "현관에서 이어진 공간"이 됨 | 불가 |
| 3. 방 상자 놓기 | 스티커 고르고 테두리 안에 드래그 | 테두리·다른 상자에 자석 스냅, 기본 크기 적용 | 원룸이면 가능 |
| 4. 남은 자리 이름 붙이기 | 옅게 표시된 잔여공간을 탭해 "여기가 거실" | 라벨 사이는 가상 경계로 자동 처리 | 가능 |
| 5. 문 확인 | 자동 문이 틀리면 벽 따라 드래그 | 상자마다 문 1개 자동 배치 | 가능 |
| 6. 창문·발코니·피난시설 | 바깥 테두리를 탭해 스티커 | 발코니는 외곽 밖에 붙음 | 가능 |

핵심은 4단계다. **어린이는 거실 모양을 그린 적이 없는데 화면에 거실이 있다.**

기본 크기는 격자 해상도에 맞춰 조정하되, 예시: 큰방 4×4, 작은방 3×3, 욕실 2×2, 드레스룸 2×3, 다용도실 2×2. 크기가 정확하지 않아도 대피 학습에는 지장이 없으므로 크기 조절은 손잡이로 나중에 하게 한다.

## 4. 데이터 모델 변경

원 보고서 5.1의 `SpaceRegion`을 두 종류로 나누고 `BoundaryRun`은 파생 캐시로 내린다.

```ts
interface FloorMap {
  id: string;
  grid: AdaptiveGrid;
  shellCells: CellRun[];
  voidCells: CellRun[];
  boxes: BoxSpace[];                 // 성격 A·B·D
  zoneLabels: ZoneLabel[];           // 성격 C — 잔여공간 위 이름표
  portals: Portal[];
  exteriorFeatures: ExteriorFeature[]; // 창, 발코니창, 경량칸막이, 완강기 등
  verticalLinks: VerticalLink[];
  // 파생 캐시 — 저장하지 않고 불러올 때 재계산
  residual?: ResidualZone[];
  boundaries?: BoundaryRun[];
}

interface BoxSpace {
  id: string;
  kind: BoxKind;                     // bedroom | bath | dressing | utility | storage | study | refuge | kitchen_closed | alpha | balcony_extended | balcony | terrace | other
  label: string;
  cells: CellRun[];
  enclosure: 'closed' | 'semi';
  openSides?: GridEdgeRun[];         // semi일 때 트인 면
  attachedTo?: string;               // 중첩(안방→드레스룸)일 때 부모 상자 id
  placement: 'inside' | 'annex';     // D는 annex(외곽 밖)
  autoDoor: boolean;                 // 어린이가 문을 옮기면 false
}

interface ZoneLabel {
  id: string;
  kind: 'living' | 'kitchen' | 'dining' | 'corridor' | 'entry' | 'other';
  cells: CellRun[];                  // 잔여공간의 부분집합, 라벨끼리 겹치지 않음
}

interface ResidualZone {             // 파생
  id: string;
  cells: CellRun[];
  reachesEntry: boolean;
}

interface ExteriorFeature {
  id: string;
  kind: 'window' | 'balcony_window' | 'light_partition' | 'descending_hatch' | 'descender';
  edges: GridEdgeRun[];
  verifiedByAdult?: boolean;         // "어른과 확인" 체크
}
```

경계 종류는 자동으로 결정된다.

| 상황 | 경계 |
|---|---|
| 상자의 변 | `wall` |
| 상자의 `openSides` | `open` |
| 라벨과 라벨 사이 | `virtual` |
| 잔여공간과 외곽 | `exterior` |

**어린이가 경계 종류를 고르는 화면이 사라진다.** 원 보고서 5.3의 표는 이 자동 규칙으로 대체된다.

## 5. 자동 규칙

### 5.1 잔여공간 계산

```text
residual = shell − ∪(boxes where placement = inside) − void
4-연결 성분으로 분리
현관 라벨을 포함한 성분 = 주 공용부
그 외 성분 = "떨어진 공간" — 경고 대상
```

### 5.2 자동 문 (닫힌 상자마다 1개)

```text
autoDoor(box):
  a = box 변 중 주 공용부와 맞닿은 구간들
  b = box 변 중 다른 상자와 맞닿은 구간들
  if a 존재:
    if box.kind ∈ {dressing, bath} and b 중 bedroom 존재:
      질문 "이 방은 어디서 들어가?" [거실·복도에서] [안방에서]
    else: a 중 가장 긴 구간 중앙에 문
  elif b 존재:
    b 중 가장 긴 구간의 상대 상자를 attachedTo로 두고 그 벽에 문
  else:
    경고 "이 방으로 들어갈 길이 없어"
```

문 위치는 `boundaryId + ratio`이므로 상자를 옮기면 따라간다.

### 5.3 반열린 상자

문을 만들지 않는다. `openSides` 기본값은 주 공용부와 맞닿은 가장 긴 변. 알파룸을 놓으면 어린이가 아무것도 하지 않아도 거실 쪽이 트인다.

### 5.4 라벨의 의미

라벨은 표시·안내용이다. 통행·연기 계산에서 잔여공간의 모든 칸은 라벨 유무와 무관하게 동일하게 취급된다. 라벨이 없는 잔여 칸은 화면에 옅은 회색으로 두고 "여기는 뭐야?"라고 한 번만 묻는다. 답하지 않아도 진행된다.

### 5.5 잔여공간이 끊길 때

상자를 놓는 도중 주 공용부가 두 조각이 되면 놓기 전 미리보기에서 빨간 점선과 함께 "이렇게 놓으면 저쪽으로 못 가"를 보여 준다. 놓는 것 자체는 허용하되, 놓은 뒤 `이 벽 트기` 또는 `문 놓기`를 제안한다. 실제 집에서 복도가 문으로 나뉘는 경우가 있으므로 금지하지 않는다.

## 6. 특수 구획 처리

| 구획 | 처리 |
|---|---|
| **드레스룸·화장대실 (중첩)** | 안방 변에 붙여 놓으면 `attachedTo = 안방`. 그래프에서는 안방을 통해서만 연결. 안방→드레스룸→욕실 체인 허용. 깊이 3 이상이면 확인 질문 |
| **알파룸** | `semi`, `openSides` 1면. 문 없음 |
| **발코니·베란다** | 스티커를 놓을 때 "거실이랑 이어져 있어(확장)?" → 예: 외곽 안 `semi` 상자 / 아니오: 외곽 밖 `annex` 상자 + 발코니창 `Portal(kind: window)` |
| **피난시설** | 발코니·외벽 위 스티커: 경량칸막이(옆집으로), 대피공간(닫힌 상자, 방화문), 하향식 피난구(`VerticalLink`), 완강기(창). 설치 여부는 집마다 다르므로 "있으면 붙여" + "어른과 확인" 체크를 둔다 |
| **현관** | 별도 방이 아니다. 현관문 `Portal` + 자동 `entry` 라벨. 중문이 있으면 라벨 경계에 `Portal` 하나 추가 |
| **피난전실·부속실** | 집 밖 공용부(F). 현관문 밖으로 복도→전실→계단 순서로 스티커를 놓는다 |
| **닫힌 주방** | 주방 스티커를 놓을 때 "주방에 문이 있어?" → 있으면 A 상자, 없으면 C 라벨 |
| **원룸** | 상자 없이 테두리 + 현관 + 욕실 상자 1개. 나머지는 잔여공간 라벨(잠자는 곳·주방) |
| **이름 모르는 공간** | "문이 있어?"만 묻고 `other`, 이름 `기타 1` |

## 7. 추천 알고리즘 단순화

원 보고서 7.4의 "모든 공간을 동시에 영역 성장"을 **상자 채우기 문제**로 바꾼다.

```text
generateCandidates(query):
  1. 외곽 후보와 현관 위치 후보를 고른다.
  2. 상자 목록을 만든다: 침실 n, 욕실 m, (드레스룸·다용도실·알파룸은 질문에 따라)
  3. 상자를 외곽 변을 따라 배치한다.
     - 침실: 외벽 접촉 필수 (창)
     - 욕실: 내부 허용, 침실 또는 공용부 인접
     - 현관 앞 2칸은 비워 둔다
  4. 잔여공간을 계산한다.
  5. 하드 제약: 잔여 성분 1개, 모든 닫힌 상자가 공용부 또는 부모 상자와 접촉
  6. 점수: 질문 일치 + 잔여공간 품질(거실 최소 면적, 복도 길이, 한 칸 목 없음)
  7. 위상 다양성으로 4개 선택 (원 보고서 7.6 유지)
```

탐색 공간이 "상자 위치 조합"으로 줄어 빠르고, 결과의 거실은 자연스럽게 L자·꺾인 형이 된다. 원 보고서의 구조 원형(7.2)은 "상자를 어느 변에 붙이는가"의 패턴으로 축소된다.

## 8. 질문 개선

| 원 질문 | 문제 | 대체 |
|---|---|---|
| "방들은 어디에 모여 있어?" (한쪽·양쪽·둘레·복도 끝) | 말로 답하기 어렵다 | 테두리 위 8구역(모서리 4 + 변 4)을 보여 주고 "방이 있는 쪽을 눌러봐". 말 대신 위치 |
| "집 바깥 테두리는?" | 유지 | — |
| "현관문을 열면 무엇이 먼저 보여?" | 유지 | — |
| "주방은 트여 있어?" | 3~5지선다 | "주방에 문이 있어?" 예/아니오로 축소. 넓은 미닫이는 문 놓은 뒤 종류 선택 |
| (없음) | 국내 아파트 판별력이 높은 질문 부재 | "거실 큰 창문 옆에 방이 있어? 몇 개?" — 판상형 2·3·4베이를 한 번에 가른다 |
| (없음) | 발코니 확장 여부 | "발코니가 거실이랑 이어져 있어?" |

`HomeQuery`에 추가: `bayCount?: 0|1|2|3`, `kitchenClosed?: boolean`, `balconyExtended?: boolean`, `bedroomSides?: Set<Side8>`. `bedroomPattern`은 `bedroomSides`로 대체.

## 9. 검증 규칙 변경

```text
validateFloor(floor):
  [기존] shell·void 겹침 없음, 모든 상자 cell이 shell(또는 annex면 shell 밖 인접) 안
  [기존] 상자끼리 겹치지 않음, 각 상자 4-연결
  closed 상자: portal ≥ 1
  semi 상자: openSides ≥ 1
  annex 상자: shell 변에 최소 1칸 접촉
  attachedTo 체인 깊이 ≤ 2 (초과 시 확인)
  라벨 cell ⊂ residual, 라벨끼리 겹치지 않음
  잔여 성분 중 현관 미포함 성분 존재 → 경고

대피 그래프:
  노드 = closed/semi 상자 + 잔여 성분 + annex + 공용부 공간 + 층
  간선 = portal(상태별), openSides, 라벨 경계(항상 통과), verticalLink
  라벨은 노드가 아니다 — 거실·주방·복도는 한 노드
```

노드 수가 원 보고서 모델보다 크게 줄어 위험장·경로 계산이 가벼워진다.

## 11. 구현 순서 조정

| 단계 | 내용 |
|---|---|
| 0 | (원 보고서 유지) 후보 4개 + 다른 모양 보기, 빠른 변형 |
| 1 | `BoxSpace`·`ZoneLabel` 스키마, 잔여공간 계산, 자동 경계 파생, 기존 `rect` → `BoxSpace(closed, inside)` 이행 |
| 2 | 테두리 → 현관 → 상자 놓기 → 라벨 → 문 확인 흐름, 자동 문, 스냅, 끊김 미리보기 |
| 3 | 중첩 상자, 알파룸(semi), 발코니 확장/annex, 피난시설 스티커 |
| 4 | 상자 채우기 추천기, 8구역 탭 질문, 베이 질문 |
| 5 | (원 보고서 유지) 도면 따라 그리기, 여러 층 |

원 보고서 1단계의 "연결 영역 점유·인접·경계 추출"은 그대로 필요하다. 달라지는 것은 어린이가 만지는 대상이 "모든 공간"에서 "상자와 라벨"로 줄어든다는 점이다.

## 12. 사용성 시험에 추가할 가설

- 어린이가 거실 모양을 한 번도 그리지 않고 완성한 평면에서 거실이 기준 집과 같은 위치에 있는가
- 첫 사용 가능한 평면까지 중앙값: 원 보고서 3분 → 2분
- "경계 종류" 관련 성인 개입 0회
- 드레스룸을 안방에 붙였을 때 문이 안방 쪽으로 자동 배치되는 것을 어린이가 "맞다"고 인식하는가
- 발코니 확장 여부 질문을 저학년이 이해하는가 (이해하지 못하면 "거실 끝에 창문 두 겹이야?"로 대체 시험)
