# 우리집 대피지도 v1.8 변경 명세

## 1. 목적과 적용 범위

이 문서는 `RESEARCH-child-home-layout.md`와 `RESEARCH-child-home-layout2.md`를 실제 앱에 적용하는
첫 호환 단계다. v1.7의 선택 캐릭터 3D화는 그대로 유지한다.

연구보고서의 최종 데이터 모델(`BoxSpace`, `ZoneLabel`, 폭을 가진 `Portal`)을 한 번에 저장 스키마에
넣으면 현재 그래프·위험장·인쇄·저장 이행을 모두 동시에 바꿔야 한다. 이번 단계에서는 어린이가
사용하는 입력 방식부터 `상자 + 잔여공간`으로 바꾸고, 그 결과를 현재 `FloorPlan`에 결정론적으로
투영한다. 저장 파일과 기존 템플릿은 그대로 열린다.

## 2. 상자와 남은 자리로 집 만들기

### 2.1 어린이가 하는 일

세 번째 시작 방법 `방부터 놓고 시작하기`를 `방 상자로 쉽게 만들기`로 바꾼다.

1. 잠자는 방 개수를 고른다.
2. 집 테두리 네 가지 중 가까운 것을 고른다.
   - 넓은 네모
   - 길쭉한 네모
   - 왼쪽이 꺾인 집
   - 오른쪽이 꺾인 집
3. 테두리 둘레의 여덟 자리에서 방이 있는 쪽을 누른다.
4. 주방에 문이 있는지만 고른다.
5. 만들어진 평면을 보고 시작하거나 이전 단계로 돌아간다.

방 자리는 방 개수만큼만 고른다. 이미 개수를 다 채운 뒤 다른 자리를 누르면 가장 먼저 고른
자리를 새 자리로 바꾼다. 선택을 지우는 별도 도구를 배우지 않아도 된다.

### 2.2 자동으로 되는 일

- 선택한 테두리를 격자 칸 집합으로 만든다.
- 침실 상자를 선택 위치와 가까운 외벽에 놓는다.
- 욕실 한 칸과, 문 있는 주방을 골랐다면 닫힌 주방 상자를 놓는다.
- `테두리 - 닫힌 상자`를 계산한 남은 자리를 거실·복도로 만든다.
- 문 없는 주방이면 남은 자리 일부에 주방 이름을 붙이고 거실과 맞닿은 벽을 전부 튼다.
- 닫힌 상자는 남은 자리와 가장 길게 맞닿은 벽 중앙에 문을 하나 만든다.
- 현관문과 침실 창문을 외벽에 자동으로 둔다.

이 과정에서 어린이는 거실의 L자 모양을 직접 그리지 않고, 벽 종류나 주방문 위치도 먼저 정하지
않는다. 시작 뒤에는 기존 고르기·옮기기·크기 조절·문 도구로 결과를 고칠 수 있다.

## 3. 결정론적 생성기

순수 계산 모듈 `core/plan/residual.ts`가 다음 순서를 지킨다.

```text
shell(shape)
  -> placeBedrooms(selectedSides)
  -> placeBathAndClosedKitchen()
  -> residual = shell - boxes
  -> rejectWhenResidualDisconnected()
  -> reserveOpenKitchenLabelWhenNeeded()
  -> rectangles = decomposeResidual()
  -> openEveryBoundaryInsideResidual()
  -> autoDoorsForClosedBoxes()
  -> frontDoorAndBedroomWindows()
  -> validateProjection()
```

같은 입력에는 항상 같은 블록과 id가 나온다. 시간과 난수를 쓰지 않는다. 상자 후보는 다음 비용을
작은 순서로 고른다.

```text
비용 = 선택한 둘레 자리와의 거리
     + 외벽에서 떨어진 침실 벌점
     + 현관 앞을 막는 벌점
     + 한 칸짜리 잔여 목 벌점
```

상자를 놓은 뒤 잔여공간이 끊기면 그 후보를 버리고 다음 후보를 쓴다. 닫힌 방은 자동 문이 실제
잔여공간과 맞닿은 경계에 있어야 한다. 개방형 주방과 잔여 직사각형 사이에는 `open_passage`를
공유 벽 전체에 만들어 2D·그래프·위험장·3D가 같은 통행 결과를 읽게 한다.

## 4. 현재 스키마로의 호환 투영

이번 단계의 잔여공간은 연결된 칸 집합을 겹치지 않는 여러 `RoomBlock` 직사각형으로 분해한다.
직사각형 사이 공유 벽은 전부 `open_passage`로 지워 하나의 공용 영역처럼 걷게 한다.

이 투영은 최종 스키마가 아니다. 다음 단계에서 저장 스키마를 올릴 때는 같은 순수 생성기의
중간 결과를 `BoxSpace + ZoneLabel`로 직접 저장한다. 이번 단계가 보존해야 하는 불변조건은 다음과
같다.

- 모든 방은 격자 안에 있고 서로 겹치지 않는다.
- 생성된 침실 수는 이용자가 고른 수와 같다.
- 닫힌 상자마다 문이 하나 이상 있다.
- 모든 잔여 직사각형은 트인 통로로 서로 도달 가능하다.
- 현관문에서 모든 침실까지 그래프 경로가 있다.
- 주방에 문이 없다고 답하면 주방과 공용부 공유 벽에 문짝이 없다.

## 5. 2D와 3D 대피연습

`CLAUDE.md`의 절대규칙에 따라 에디터와 실시간 게임은 공용 SVG를 쓰고, 3D는 리플레이 화면에만
둔다. 따라서 두 방식은 다음처럼 한 판으로 이어진다.

```text
2D 대피 게임
  -> 결과 리포트
  -> 같은 판을 1인칭 3D로 다시 보기
```

### 5.1 2D 안전 미션 진행판

게임에 점수·등급·순위를 넣지 않는다. 대신 지금 판에서 연습할 네 행동을 항상 보인다.

1. 연기가 보이면 몸 낮추기
2. 문을 열기 전에 손등으로 확인하기
3. 지나온 문을 닫기
4. 나가는 곳에 도착하기

해당 행동을 하면 원형 확인 표시와 짧은 권유형 문구로 바뀐다. 집 구조상 문을 만지거나 닫을 수
없는 판에서는 그 항목을 `이 판에는 없음`으로 표시해 실패처럼 보이지 않게 한다. 진행판은 화면
가장자리에 고정하고 도면과 방향 단추를 가리지 않는다. 실패하더라도 완료한 행동은 그대로 남긴다.

### 5.2 3D 방식

- 3D 리플레이의 기본 시점은 1인칭이다.
- 2D에서 고른 `playerCharacter`를 같은 판의 주인공으로 쓴다.
- 1인칭에서는 몸을 감추고 눈높이·낮은 자세·이동 방향을 카메라에 반영한다.
- 3D를 지원하지 않으면 동일 기록을 2D로 재생한다.
- 3D가 실시간 게임 규칙을 따로 갖지 않는다. 기록된 셀·문 상태·위험장을 읽어 2D 판과 결과가
  달라지는 일을 막는다.

## 6. 검증

### 6.1 순수 연산

- 테두리 4종 × 침실 1~4개 × 주방 2종을 전수 생성한다.
- 블록 겹침·격자 이탈·침실 수·닫힌 방 자동 문을 검사한다.
- 잔여공간 연결성과 현관문에서 침실까지의 그래프 경로를 검사한다.
- 같은 입력 두 번의 JSON이 완전히 같은지 검사한다.
- 개방형 주방 공유 경계가 모두 `open_passage`인지 검사한다.

### 6.2 브라우저와 시각 검증

- 세 번째 시작 방법으로 들어가 테두리와 방 위치를 바꾸면 미리보기가 달라지는지 확인한다.
- 선택한 수보다 많은 방 위치를 눌러도 선택 수가 늘지 않는지 확인한다.
- 생성된 평면으로 온보딩이 끝나고 내 자리 단계가 이어지는지 확인한다.
- 게임의 안전 미션 진행판이 도면·방향 단추와 겹치지 않는지 확인한다.
- 몸 낮추기·문 확인·문 닫기·도착 행동이 진행판에 반영되는지 확인한다.
- 결과에서 3D 리플레이를 열면 1인칭이 기본이고 같은 선택 캐릭터가 전달되는지 확인한다.

화면을 바꿨으므로 최소 1280×800과 1440×900에서 캡처해 테두리 선택, 여덟 자리 선택,
생성 미리보기, 2D 미션 진행판, 1인칭 3D를 눈으로 확인한다.

## 7. ElevenLabs 전체 음성 자산

`public/voice/`를 사람 음성의 단일 정본으로 쓴다. 이 폴더에는 `Juwonmom` 목소리로 만든
MP3와, 정본 콘텐츠에서 다시 만들 수 있는 `manifest.json`을 둔다. 가이드 규칙 84개는
쉬움·보통 두 수준으로 갈리므로 168개이고, 게임 핵심 음성 8개를 더해 전체 생성 대상은
176개다. 방 이름과 피난설비 이름이 실행 중 정해지는 네 변형은 화면 문구만 개인화하고 음성은
뜻이 같은 일반화 문장으로 녹음한다.

재생과 배포는 다음 원칙을 지킨다.

- 웹 배포본은 `NEXT_PUBLIC_BASE_PATH`를 포함한 `/voice/{파일명}`에서 현재 규칙 id와 이용 수준에
  맞는 MP3를 먼저 재생한다.
- 파일이 없거나 재생이 실패하면 같은 화면 문장을 브라우저 한국어 TTS로 읽는다.
- 단일 HTML 오프라인 배포본은 4MB 상한을 지키기 위해 핵심 8개만 data URI로 내장하고,
  가이드 음성은 브라우저 TTS로 대체한다.
- `npm run voice`는 `public/voice/`의 핵심 8개만 `src/content/voice.ts`에 굽는다.
- 소리를 끄거나 화면을 떠날 때 웹 MP3, 내장 MP3, 브라우저 TTS를 모두 즉시 멈춘다.
- 자동 생성기는 유효한 기존 MP3를 건너뛰어 중복 크레딧을 막고, 다운로드마다 1KB 이상과
  ID3 또는 MP3 프레임 헤더를 검사한다.

전체 파일명과 일반화 문장은 `public/voice/manifest.json`, 사람이 읽는 근거와 용량 결정은
`docs/VOICE-MANIFEST.md`를 정본으로 한다.

## 8. 소개 화면 진입 규칙

PC에서 페이지를 새로 열거나 새로고침하면 교육 목적과 시작 단추가 있는 소개 화면을 항상 먼저
보인다. 세션 저장소에 `이미 봄` 표시를 남기지 않는다. 시작 단추를 누른 뒤에는 로컬에 저장된
지도가 있으면 그대로 복원하므로, 소개를 다시 보는 것이 작업 초기화를 뜻하지 않는다.

## 9. 여닫이문과 미닫이문

기본 팔레트에서 `여닫이문`과 `미닫이문`을 나란히 보여 어린이가 실제 집의 문 여는 방식을
고른다. 둘 다 방의 출입문, 필수 방문, 그래프 통행, 위험 확산 차단, 게임의 문 확인·열기·닫기
행동으로 동일하게 취급한다. 차이는 그림과 움직임이다.

- 여닫이문은 경첩과 회전 호로 앞뒤로 여는 모습을 그린다.
- 미닫이문은 두 줄 레일과 겹치는 문짝으로 옆으로 미는 모습을 그린다.
- 3D에서 닫힌 미닫이문은 통로를 막고, 열리면 문짝이 벽 옆으로 포개진다.
- 자동 생성기는 문 종류를 대신 추측하지 않고 기존 여닫이문을 기본으로 둔다. 이용자가 실제 집을
  보며 미닫이문으로 바꿀 수 있다.
- 미닫이문을 처음 놓았을 때는 검증된 기존 방문 안내와 같은 음성을 재사용해 음성 정본을 늘리지
  않는다.
