# PC 게임형 3D 리플레이 개편 계획서

작성일: 2026-08-31  
대상: 초등학생용 「우리집 대피지도」의 결과 뒤 3D 리플레이  
구현 정본: `docs/DESIGN-v1.10-changes.md`

## 1. 목적

현재 3D 리플레이는 아이가 고른 캐릭터와 실제 대피 기록을 3차원으로 보여 주지만, 집과 바닥의
표면이 단순하고 카메라 조작이 오른쪽의 작은 설정 패널에 묻혀 있다. 이 개편은 3D 리플레이를
PC 게임 화면처럼 또렷하고 풍부하게 보이도록 만들고, 아이가 설명을 읽지 않아도 상단의 큰 시점
단추와 방향 단추 또는 마우스로 쉽게 둘러보게 하는 것이 목적이다.

이 화면은 게임 결과를 다시 보는 기능이다. 2D 대피 게임을 3D 게임으로 바꾸거나 점수·순위·시간제한을
추가하지 않는다.

## 2. 현재 구현 진단

| 항목 | 현재 상태 | 문제 | 개편 기준 |
|---|---|---|---|
| 해상도 | `low` 1배, `high` 최대 1.8배 DPR | 고밀도 PC에서 모서리와 글자가 무르게 보일 수 있다 | `고급` 최대 2.25배, `높음`, `가벼움` 3단 |
| 카메라 | 1인칭·뒤에서·집 전체 | 마우스 회전값이 집 전체 시점에만 반영된다 | 세 시점 모두 좌우 회전과 위아래 보기 반영 |
| 시점 UI | 288px 오른쪽 패널 안의 작은 3분할 단추 | 중요 조작인데 발견하기 어렵다 | 화면 상단에 48px 이상 큰 시점 단추 3개 고정 |
| 방향 조작 | 마우스 끌기·휠 안내 한 줄 | 위·아래·왼쪽·오른쪽을 눈으로 고를 단추가 없다 | 상단 방향 단추 4개와 가운데 원위치 단추 제공 |
| 실내 | 정점 색 한 벌의 바닥·벽·가구 | 색은 다르지만 나무·타일·천·금속 표면 구분이 약하다 | 절차형 바닥 무늬, 몰딩, 러그, 천장과 천장등 추가 |
| 실외 | 평면 잔디·보도·저해상도 나무 | 집이 빈 판 위에 놓인 느낌이 강하다 | 보도 블록, 진입로, 잔디 띠, 관목, 가로등, 다층 나무 |
| 빛 | 반구광·태양광·채움광·불빛 | 실내가 평평하고 재질 반사가 약하다 | 영화형 톤 매핑, 부드러운 그림자, 실내등, AO 단계화 |
| 화재 | 카메라를 보는 원형 불·연기 판 | 불이 둥근 스티커처럼 보인다 | 입체 불꽃 코어와 연기층을 분리하되 점멸하지 않는다 |
| 성능 | 느리면 `high`에서 `low`로 한 번 하향 | 고사양 PC의 여유를 쓰지 못한다 | `고급 → 높음 → 가벼움` 순서로 안전하게 하향 |

## 3. 사용자 경험 목표

1. 화면을 열자마자 상단에서 `내 눈으로`, `뒤에서`, `집 전체`를 발견한다.
2. `내 눈으로`에서도 마우스를 끌어 천장·바닥·좌우 문을 둘러볼 수 있다.
3. 마우스가 어려운 아이는 상단의 `위`, `아래`, `왼쪽`, `오른쪽` 단추를 누른다.
4. 방향을 잃으면 가운데 `정면` 단추로 즉시 돌아온다.
5. 집 안에서 나무 바닥, 타일, 러그, 몰딩, 조명과 가구 재질 차이를 알아본다.
6. 화질을 직접 고를 수 있고 느린 PC에서는 앱이 기능을 잃지 않은 채 한 단계 낮춘다.

## 4. 화면 설계도

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 3D 대피 리플레이   8초  │ 어디서 볼까? [내 눈으로] [뒤에서] [집 전체] │
│                       │ 둘러보기 [위] [아래] [왼쪽] [오른쪽] [정면] [닫기] │
├──────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│                         고해상도 3D 장면                                     │
│                  ┌──────────── 화면 설정 ────────────┐                        │
│                  │ 재생 · 처음 · 한 칸 · 빠르기      │                        │
│                  │ 길/자취/불과 연기/풍경 · 화질     │                        │
│                  └───────────────────────────────────┘                        │
│                                                                              │
│  마우스로 끌어 둘러봐     몸을 낮추고 지나간다.                              │
├──────────────────────────────────────────────────────────────────────────────┤
│ ━━━━━━━━━━━━━━━━━━━━━━━━━ 시간 이동 ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ │
└──────────────────────────────────────────────────────────────────────────────┘
```

- 상단 조작부는 장면 위에 떠서 일부를 가리는 대신 독립 행을 차지한다. 캔버스가 단추를 덮지 않는다.
- 1024px PC에서도 시점·방향·닫기 단추가 가로 스크롤 없이 보인다.
- 오른쪽 패널은 중요도가 낮은 재생·겹·화질 설정만 맡는다.
- 현재 상황 자막과 마우스 안내는 장면 아래쪽 유리판에 표시한다.

## 5. 기술 구조

```text
Replay3D
├─ CameraToolbar     시점·방향·정면·닫기
├─ Canvas            DPR·톤 매핑·부드러운 그림자
│  └─ Scene
│     ├─ Rig         3시점 공통 yaw/pitch/zoom
│     ├─ House       검증된 평면→벽·문·가구 정점
│     ├─ Interior    절차형 바닥·러그·몰딩·천장등
│     ├─ Ceiling     1인칭 천장 · 뒤에서/집 전체는 컷어웨이
│     ├─ Outside     보도·진입로·관목·가로등·나무
│     ├─ Hazard      입체 불꽃·층별 연기
│     └─ Avatar3D    선택 캐릭터·걷기·몸 낮추기·1인칭 손
├─ ReplayCaption     시간·행동 설명·마우스 안내
├─ Hud               재생·속도·겹·화질
└─ Timeline
```

외부 GLTF, HDRI, 이미지 텍스처, 웹폰트를 추가하지 않는다. 표면 무늬는 런타임 캔버스에서
결정론적으로 만들며, 배포 HTML 용량과 오프라인 조건을 유지한다.

## 6. 화질 단계와 성능 예산

| 단계 | DPR | 그림자 | AO·블룸 | 표면·장식 | 실내등 | 대상 |
|---|---:|---|---|---|---|---|
| 고급 | 1.35~2.25 | 4096, 부드럽게 | 모두 | 512px 절차 무늬·전체 장식 | 켬 | 8코어 이상 PC |
| 높음 | 1~1.75 | 2048, 부드럽게 | 가볍게 | 256px 절차 무늬·주요 장식 | 켬 | 일반 교실 PC |
| 가벼움 | 1~1.15 | 끔 | 끔 | 단색 바닥·최소 장식 | 끔 | 저사양·소프트웨어 렌더러 |

- 고급/높음 목표는 30~60fps, 자동 하향 기준은 24fps 미만이다.
- 자동 측정 전 1.5초는 셰이더·텍스처 준비 시간으로 제외한다.
- 기능은 어느 단계에서도 동일하다. 길·자취·불·연기·표지·자막·카메라 조작은 남는다.
- 단일 오프라인 HTML은 4MB 미만, 외부 요청 0건을 유지한다.

Three.js 공식 문서에 따라 렌더러 출력은 sRGB, 톤 매핑은 영화형 곡선, 그림자는 PCF 계열의
부드러운 그림자를 사용한다. `MeshPhysicalMaterial`은 픽셀 비용이 더 크므로 유리·광택 장식처럼
효과가 눈에 띄는 소수 표면에만 제한한다.

- [Three.js WebGLRenderer](https://threejs.org/docs/pages/WebGLRenderer.html)
- [Three.js 색 관리](https://threejs.org/manual/en/color-management.html)
- [Three.js MeshPhysicalMaterial](https://threejs.org/docs/pages/MeshPhysicalMaterial.html)
- [React Three Fiber Canvas](https://r3f.docs.pmnd.rs/api/canvas)

## 7. 구현 순서

1. 상단 시점·방향 조작부와 1024px 배치부터 만든다.
2. `Rig`에 세 시점 공통 yaw/pitch를 적용하고 방향 단추·방향키·마우스를 같은 상태로 묶는다.
3. 화질을 3단으로 바꾸고 DPR·그림자·후처리·장식 수준을 한 설정 객체에서 결정한다.
4. 천장, 절차형 바닥, 러그, 몰딩, 천장등과 실내 채움광을 추가한다.
5. 실외 보도·진입로·관목·가로등·나무를 개선하고 불꽃을 입체화한다.
6. 자동 테스트, 1024×768/1440×900 캡처, 프레임 하향, WebGL 실패 2D 대체를 확인한다.

## 8. 검증 계획

### 자동 조작

- 상단에 시점 단추 3개와 방향/정면 단추 5개가 있고 모두 48×48 이상인지 확인한다.
- 기본 시점이 1인칭이며 세 시점을 각각 전환할 수 있는지 확인한다.
- 1인칭에서 마우스 드래그 뒤 yaw와 pitch가 모두 변하는지 확인한다.
- `위·아래·왼쪽·오른쪽` 단추와 키보드 방향키가 카메라 상태를 바꾸는지 확인한다.
- `정면`이 yaw 0, pitch 0, zoom 1로 되돌리는지 확인한다.
- 고급·높음·가벼움 3단을 바꾸어도 WebGL 캔버스가 유지되는지 확인한다.
- 천장·실내 디테일·외부 장식 데이터 표지가 화질 단계에 맞게 존재하는지 확인한다.

### 화면 확인

- 1024×768: 시점과 방향 단추가 잘리지 않고 오른쪽 패널과 겹치지 않는다.
- 1440×900: 장면 비율과 상단 조작부의 여백이 과하지 않다.
- 1인칭: 천장·바닥·문·창·손이 보이고 화면 중앙이 가려지지 않는다.
- 집 전체: 잘린 벽 안쪽 바닥 무늬와 길이 읽힌다.
- 뒤에서: 선택 캐릭터의 머리·옷·소품과 그림자가 읽힌다.

## 9. 음성 범위

이번 개편은 3D 화면의 고정 조작 문구와 그래픽만 바꾼다. 캐릭터가 실제로 말하는 문장을
추가·수정하지 않으므로 ElevenLabs MP3 생성 대상이 아니다.
