# 우리집 대피지도

초등학생이 **우리 집을 블록으로 만들고**, 대피할 길을 그리고, **불이 난 집에서 직접 빠져나와 보는**
재난안전 학습 웹 앱이다. 끝나면 잘한 점과 고칠 점을 정리해 주고, 그때 그 장면을 **3D 로 다시 보여 주고**,
집에 붙일 **A4 대피지도 한 장**으로 뽑아 준다.

새 탭에서 처음 열면 행복한 어린이와 소방청 공식 캐릭터가 함께하는 소개 화면이 교육 목적을 알려 주고,
큰 「우리집 대피지도 그리기」 단추로 활동을 시작한다. 이어 PC 화면 크기를 확인하고 학교·학년·반·이름을
입력한 뒤 지도 만들기로 들어간다. 새로 접속하거나 새로고침해도 이 순서를 빠뜨리지 않는다.

- 설치·회원가입·서버가 필요 없다. 브라우저만 있으면 된다.
- 그린 지도와 놀이 기록은 **서버로 전송되지 않는다.** 모든 연산과 저장은 이용자 기기 안에서만 이뤄진다.
- 인터넷이 없는 교실을 위해 **HTML + 음성 폴더 배포본**을 제공한다. USB로 함께 옮겨 HTML을 더블클릭하면 열린다.
- 대피 게임과 어린이 리포트에는 **점수·등급·순위를 매기지 않는다.** 시계는 줄어드는 제한이 아니라
  늘어나는 시각이고, 실패해도 잘한 점이 하나는 나온다. 캠페인 대시보드에는 안전 항목을 얼마나
  완성했는지 알려 주는 100점 기준 `안전 완성도`만 표시한다.
- **PC 전용**이다. 너비 1024px 미만에서는 본 기능을 실행하지 않고 PC 이용 안내를 보여 준다.

> 이 앱의 확산 해석은 소방 교육자료에서 통용되는 눈높이 수치를 채택한 **교육용 근사 모델**이며,
> 성능위주설계(FDS 등) 해석을 대체하지 않는다. 또한 **법정 피난안내도를 대체하지 않는다.**

## 왜 만들었나

공동주택 화재 사망자의 다수가 연기·유독가스 흡입(77.9%)과 야간 인지 지연(19–07시 61.6%)에서 발생한다.
집집마다 평면과 피난시설이 제각각이라 "우리 집 기준"의 대피계획이 필요하지만, 아이가 직접
그려 보고 몸으로 익혀 볼 도구가 없었다.

## 하는 일

```
소개 ──▶ PC 확인 ──▶ 학교·학년·반·이름 ──▶ 템플릿 / 직접 그리기 6단계
                                                │
                                                ▼
대시보드 ◀── 그리기 ──▶ 대피경로 ──▶ 2D 대피 게임 ──▶ 결과 ──▶ 1인칭 3D 리플레이
```

| 축 | 하는 일 |
|---|---|
| 소개 | 행복한 어린이가 대피지도를 보는 배경과 소방청 공식 캐릭터 영이·일구·웅이를 보여 준다. 화재 때 신속하게 대피하는 방법을 미리 연습한다는 목적을 짧게 설명하고, 큰 시작 단추와 소방 심벌·부평소방서 표기로 활동의 출처와 다음 행동을 분명히 한다. 접속하거나 새로고침할 때마다 먼저 보인다. |
| 그리기 | 시작은 **템플릿으로 빠르게 시작**과 **직접 그리기** 두 갈래다. 직접 그리기는 준비된 외곽 8종을 고르거나 격자에 모서리를 찍어 외곽선을 직접 그린 뒤, `① 집 모양 ② 실·문·창·크기 ③ 가구·공간 이름 ④ 소화기 ⑤ 내 방·내 위치 ⑥ 같이 모이는 곳` 순서로 진행한다. 방을 놓은 **같은 2단계에서 바로 끌어 옮기고 손잡이 또는 가로·세로 단추로 크기를 조정**하며, 현관 공간도 선택 즉시 같은 방식으로 줄이고 늘린다. 2단계에는 **욕실·현관·발코니(베란다)·트인 주방(부엌) 바로 추가 단추**가 항상 보인다. 트인 주방(부엌)은 남은 바닥에서 범위를 끌어 그리며 거실과의 벽이 생기지 않고, 다시 그리면 위치와 크기가 교체된다. 벽과 문이 있는 독립 주방은 왼쪽 `주방(부엌)`을 놓는다. 침실·욕실·현관·옷방·다용도실·피난전실·기타실은 벽 있는 독립실로 놓고, **남은 바닥은 거실·복도·베란다·주방(부엌) 같은 열린 공간으로 끊김 없이 자동 연결**한다. 침대·소파·책상·옷장·책장·식탁·냉장고·티브이·싱크대·컴퓨터·세탁기·건조기·가스불은 서로 다른 기본 크기와 종류별 조절 범위를 가지며, 고른 뒤 가로·세로를 한 칸씩 바꾼다. 침대와 가스불은 모두 `가구` 갈래에 있다. 선택한 방·공간·문·창·가구·표시는 화면의 삭제 단추 또는 Delete/Backspace 키로 지우며, 열린 공간 용도는 거실 바닥으로 되돌린다. 집 외곽은 굵은 선 하나로 이어지고 실제 독립실만 내부 벽을 그리므로 흰색으로 벽을 지운 흔적이 보이지 않는다. 가구·내 위치·만나는 곳도 다시 끌어 옮길 수 있다. 문이 없는 독립실은 캐릭터가 방 이름을 말하고 문 도구와 방을 강조한다. 팔레트 클릭 → 도면 클릭이면 표준 크기로 놓이며, 마우스가 없어도 Tab·방향키·Enter 로 다 된다. |
| 필수와 그 밖 | 현관문·방문·내 자리·소화기·감지기가 **필수**다. 팔레트에 채움 표시가 붙고 점검 막대에 `있어야 하는 것 3/5` 가 뜬다. 빠진 채로 시작하려 하면 한 번만 물어보고, 막지는 않는다. |
| 문·창 | 여닫이문·현관문·미닫이문과 여닫이창·미닫이창을 고를 수 있다. 여닫이 종류와 현관문은 **1~3칸 너비**, 미닫이 종류는 **1~6칸 길이**이며 선택 즉시 보이는 `줄이기`·현재 칸 수·`늘리기`로 한 칸씩 바꾼다. 현관문은 조작부에 `현관문 너비`라고 분명히 표시한다. 개구부마다 **평소 열림/닫힘**이 있으며 도면에 그대로 보이고 한 번 눌러 바꾼다. 방화문 닫힘이 방문 닫힘보다 잘 막고, 닫힌 창은 연기를 막고, 열린 창은 오히려 돕는다. |
| 나가는 곳 | 1층 밖·**옥상**·**지하** 세 갈래다. 평소 길은 아래로 나가고(RULE-F-08), 불이 나면 지하로 내려가지 않는다(RULE-F-09). |
| 경로 | **주 경로**(현관)와 **보조 경로**(현관으로 못 나갈 때) 두 줄. 규칙 엔진이 각각 다른 `ScenarioKey` 로 평가한다. |
| 게임 | 2D 위험장 엔진. 발화점은 매번 랜덤이되 **시작 즉시 이길 수 없는 판은 내지 않는다.** 연기가 불보다 빠르고, 닫힌 문이 확산을 늦추며, 낮은 자세가 노출을 줄인다. 점수 대신 **몸 낮추기·문 확인·지나온 문 닫기·나가는 곳 도착** 안전 행동을 한눈에 보이고, 해낸 행동에만 확인 표시를 붙인다. 처음에는 목표 둘만 제시하는 `차근차근`, 익숙해지면 화재 위치가 넓어지는 `새로운 상황`, 충분히 연습하면 연기와 시간을 더 살피는 `안전 행동 도전`으로 자동 조절한다. 결과에서 **같은 상황 다시**와 **새로운 상황**을 따로 고를 수 있다. 해당 판에 문이 없으면 실패가 아니라 `이 판에는 없음`으로 알려 준다. 불과 연기는 단계로 나눠 그려 번져 나가는 앞머리가 보인다. 엔진(`core/hazard/field.ts`)에는 재난 이름이 없고 프리셋 JSON 으로 받는다. |
| 시계 | **늘어나는 시각**이다. 줄어드는 제한이 아니라 나가기까지 몇 초 걸렸는지를 보이고, 성공하면 자기 최고 기록과 나란히 뜬다. 등수는 없다. |
| 소리 | 시작 신호음·감지기 경보(실물 T-3 패턴)·발소리·문 여닫는 소리·자세 소리·성공 팡파르를 Web Audio로 합성한다. 상단바에서 끄면 예약된 효과음과 읽던 말까지 멎고, **실패에는 아무 소리도 내지 않는다.** 실제 캐릭터 발화 168개는 웹과 오프라인 모두 **`Juwonmom`·Speed 1.0 MP3로만** 읽는다. 자동 안내를 놓치면 말풍선의 **목소리 다시 듣기**를 누를 수 있고, 소리를 다시 켜는 클릭에서도 최근 MP3를 곧바로 재생한다. 예전 핵심 대사 중복 호출과 브라우저 한국어 TTS 대체 경로는 제거했다. 호환 보관 8개를 포함해 `public/voice/`의 MP3 176개를 정본·제작 서명·해독까지 전수 검사한다. |
| 3D 리플레이 | 리포트에서 「3D 로 다시 보기」를 누르면 같은 판을 PC 게임 화면처럼 재생한다. 기본은 **내 눈으로 보는 1인칭**이며 고른 캐릭터의 옷 색을 쓴 어깨·소매·손·손가락이 한 몸으로 연결되어 보이고, 뒤에서 보기와 벽을 잘라 보는 집 전체 시점도 있다. 전신 캐릭터는 기존보다 20% 낮추고 다리·몸통·팔을 짧게, 머리를 상대적으로 크게 만들어 초등학생 체형으로 보이게 했다. 1인칭 서기·낮추기 눈높이도 함께 낮췄다. 한 시점에는 1인칭 몸 또는 전신 아바타 **딱 하나만 생성**하며 숨긴 전신과 양팔을 동시에 두지 않는다. 게임 시작 직전에 내 위치를 한 개로 정리하고 리플레이 장면에서는 고정 내 위치 표시도 완전히 제거한다. 세 시점 모두 **마우스 좌우·상하 드래그, 휠, 키보드 방향키, 상단의 큰 상하좌우 단추**로 둘러볼 수 있다. 가장 중요한 「어디서 볼까」는 캔버스를 가리지 않는 상단 전용 바에 48px 이상 버튼으로 표시한다. Hology가 강조하는 지형·재질·자연스러운 캐릭터 이동·사용자 셰이더 표현을 참고해 1024 절차형 표면, 최대 DPR 2.5, 이방성 필터 16, 부드러운 그림자와 접촉 그림자를 적용했다. 잔디·보도·도로·수목·이웃집·가로등과 바람에 흔들리는 풀을 코드로 만들어 오프라인에서도 게임 장면의 깊이를 유지한다. **고급·높음·가벼움** 세 화질이 화면 배율·그림자·표면 무늬·장식·후처리를 함께 조절하며, 느린 기기에서는 한 단계씩 자동으로 내린다. 아이가 그린 길과 지나온 자취, 나가는 곳·불난 곳 표지는 그대로 보이고 WebGL을 못 쓰면 2D로 내려간다. |
| 리포트 | 규칙 엔진(정적)과 플레이 로그(동적)를 합쳐 **잘한 점 / 고칠 점**으로 정리한다. 실패해도 잘한 점이 하나는 있고, 고칠 점은 세 개까지만 보인다. `[왜?]` 를 누르면 학습 카드가 그 자리에서 펼쳐진다. 연습을 마치면 한 주에 한 번 **참 잘했어요 도장**을 찍고, 안전 행동에 따라 배지 8종을 모은다. 상단의 안전수첩에서 4주 약속표·배지·최근 연습을 함께 본다. 점수·등급·순위는 없다. |
| 캠페인 대시보드 | 상단 `사용법` 오른쪽의 `대시보드`는 `/dashboard/`라는 **별도 통합포털**이다. 시도→시군구→읍면동→학교/어린이집→학년/연령→반의 종속 필터와 5개 핵심 지표뿐 아니라, **소방기관·교육기관·가정의 균형 있는 역할 허브**, 교육 설계→교실 학습→가정 실천→결과 환류의 4단계 순환, 표준 교육과정, 역할별 오늘 할 일, 주간 일정, 학생 활동 모니터링, 통합 자료실을 한 체계로 제공한다. 친구끼리 등수를 매기지 않고 도움이 필요한 안전 항목을 찾는다. 현재 정적 GitHub Pages 버전은 가상 자료와 **같은 PC 브라우저 안의 기록만** 보여 주며 개인정보·집 도면을 서버로 보내지 않는다. 여러 기관의 중앙 관리는 보호자 동의·로그인·역할 권한·감사기록·서버를 갖춘 후속 배포가 필요하다. |
| 캐릭터 | 영이·웅이(설명)와 일구(발견·격려)가 **트리거 기반**으로 먼저 말을 건다. 자유 입력·검색은 없다. "이제 뭘 해야 해?"는 어느 단계에서든 답한다. 말풍선은 도면 아래 **고정 높이 해설 칸**에만 나타나므로 지도를 가리지 않고 도면 크기도 바꾸지 않는다. 게임에서 내가 될 캐릭터는 **남학생 5명·여학생 5명** 열 명 중에 고른다. 얼굴 뼈대와 칠하는 방식은 같고 머리 모양·머리 색·피부 톤·옷 색·소품으로 갈린다. |
| 인쇄 | A4 세로 한 장 — 주·보조 경로, 못 나갈 때 미니맵, 우리 가족 약속, 손글씨 칸, 119, 가족과 함께 확인할 것. 흑백에서도 번호·선종류로 읽힌다. |

콘텐츠(학습 카드·캐릭터 대사·판정 문장·규칙 문장)는 `src/content/` 의 JSON 이다.
모든 문장에 출처 id 가 있고, 출처가 **1차 대조 전**이면 화면에 "검수 대기"로 표시된다.
`npm run validate` 는 구조 오류만 막고, `npm run validate:strict` 는 미검수 출처도 막는다
(소방청 원문 대조가 끝나면 배포 워크플로를 strict 로 바꾼다).

설계서는 `docs/DESIGN-v1.0.md` 와 변경 명세 `docs/DESIGN-v1.1-changes.md`부터
`docs/DESIGN-v1.16-changes.md`까지다. 어긋나면 뒤 문서가 이긴다.
받은 지시와 그 처리 상태는 `docs/REQUESTS.md` 에 모아 둔다.

## 현재 구현과 연구 제안

현재 편집기는 빠르게 시작하는 데 초점을 둔 **24×16 격자·직사각형 독립실 모델**이다. 온보딩에서
`템플릿으로 빠르게 시작`과 `직접 그리기` 중 하나를 고른다. 템플릿은 준비된 전체 평면을 바로
수정하고, 직접 그리기는 외곽 8종을 고르거나 격자에 직교 외곽선을 직접 그린다. 빈 집 안에 실제
독립실을 하나씩 놓으면 남은 바닥이 거실·복도·현관·주방 같은 열린 공간으로 자동 구성된다. 이후
6단계 길잡이에서 실·문·창의 배치·크기, 가구·이름, 소화기, 내 위치, 모이는 곳을 차례로 완성한다.

다음 표의 연구 제안은 [연구보고서](./docs/RESEARCH-child-home-layout.md)에 설계와 알고리즘이 정리돼 있을 뿐,
아직 앱에 구현된 기능이 아니다.

| 항목 | 현재 구현 | 연구 제안 — 아직 미구현 |
|---|---|---|
| 방과 집 외곽 | 방마다 직사각형 `RoomBlock.rect`, 고정 24×16 격자. `FloorPlan.shell` 외곽을 먼저 만들고 `closed` 독립실과 벽 없는 `zone` 공용 바닥을 구분한다 | 이어진 칸 영역으로 T·U자와 더 자유로운 불규칙 외곽 표현 |
| 문과 트인 곳 | 한 셀의 한 벽면에서 시작하는 여닫이 1~3칸·미닫이 1~6칸 개구부. 공용 구역 사이 `open_passage`는 통행 계산에만 쓰고 2D·3D에는 벽을 만들지 않는다 | 접이문·곡선 경계·가상 경계 |
| 집 고르기 | 전체 외곽 8종 갤러리 또는 격자 직교 외곽선 직접 그리기 | 외곽·현관·복도·방 배치·주방 관계를 묻는 적응형 질문과 위상적으로 다른 후보 추천 |
| 직접 만들기 | 외곽을 만든 뒤 팔레트에서 직사각형 독립실을 하나씩 놓고 남은 바닥을 자동 연결 | 도면 이미지를 로컬에서 따라 칠하기, 방 색칠·나누기·합치기·벽 밀기 |
| 층 | 한 평면의 `home`·`common` 레이어 | 여러 주거 층과 계단·하향식 피난구를 잇는 층간 그래프 |
| 자동 생성 | 외곽 연결성 검증, 독립실 배치 뒤 잔여 공용 바닥 재구성, 열린 공간 자동 연결 | 공간 관계 그래프의 우선순위를 더 받아 부분 재배치 |

“모든 집”은 건축 CAD처럼 길이와 곡선을 완전히 복제한다는 뜻이 아니다. 연구 목표는 템플릿을 새로
코딩하지 않아도 공간·경계·출구·피난설비의 **연결 관계와 대피 가능성**을 보존하는 것이다.
소개 화면은 접속하거나 새로고침할 때마다 먼저 보이며, 시작 단추를 누르면 저장된 작업을 이어서 연다.
현재 미이행 상태와 우선순위는 [요청 관리대장](./docs/REQUESTS.md)의 `하는 중`·`대기` 표가 정본이다.

## 배포

### 정적 웹

```bash
npm run build            # out/ 생성
```

`out/` 을 아무 정적 호스팅에나 올리면 된다. GitHub Pages 프로젝트 페이지처럼 하위 경로에
게시할 때는 기준 경로를 준다.

```bash
BASE_PATH=/저장소이름 npm run build
```

`main` 에 푸시하면 검증을 통과한 경우에만 GitHub Pages 로 배포하는 워크플로가
포함되어 있다(`.github/workflows/deploy.yml`). 저장소 설정에서
**Settings → Pages → Source: GitHub Actions** 를 한 번 지정하면 된다.

### 오프라인 배포본

```bash
npm run build:standalone
```

`dist/home-escape-map.html`과 `dist/voice/` 폴더를 함께 USB로 옮기면, 인터넷이 없는 교실에서도
더블클릭으로 열린다. 외부 네트워크 참조가 0건이 되도록 CSS·JS와 소개 화면 이미지를 문서 안으로
넣고, Juwonmom MP3 176개는 HTML 옆 로컬 폴더에서 읽으며 웹폰트는 시스템 글꼴로 대체한다.

HTML 에서 `<link>` 를 지우는 것만으로는 부족하다. Next.js 는 같은 참조를 스트리밍
페이로드에도 실어 보내고, 수화 과정에서 React 가 그것을 다시 넣기 때문이다. 그래서
빌드 자체를 오프라인 모드로 다시 돌려 웹폰트를 아예 렌더하지 않게 하고, 페이로드에 남은
스타일시트 경로는 내용이 담긴 data URL 로 바꾼다. `npm run smoke` 가 `file://` 에서
네트워크 요청 0건·오류 0건을 실제로 확인한다.

### 데스크톱 앱(Electron)으로 감쌀 때

바깥 세계에 닿는 코드를 `src/platform/` 한 곳에 모아 두었다. Electron 껍데기는
`Host` 를 구현해 `setHost()` 로 한 번 갈아 끼우기만 하면 되고, 나머지 코드는 손대지 않는다.

| 자리 | 웹 | 데스크톱에서 바꿀 것 |
|---|---|---|
| `platform/host.ts` | `localStorage` · `sessionStorage` · `<a download>` | 파일 시스템 · 저장 대화상자 |
| `platform/raster.ts` | 캔버스로 SVG→PNG | 그대로 쓴다 |

`npm test` 가 이 경계를 지킨다 — `platform/` 밖에서 브라우저 저장소나 파일 내려받기를
만지면 실패한다. 화면은 이미 `file://` 에서 네트워크 없이 도는 것이 검증돼 있으므로,
`out/` 또는 `dist/`의 HTML과 음성 폴더를 그대로 실어 주면 된다.

### 핵심 알고리즘

**위험장** — 매 프레임 물리 연산 대신 칸마다 연료·감쇠를 두고 단계적으로 번지게 한다.
문·창이 열렸는지 닫혔는지, 방화문인지에 따라 감쇠가 달라지고, 연기가 불보다 빠르다.
엔진 자체는 재난 이름을 모르고 `content/hazards/*.json` 프리셋이 속도와 연료를 준다.
그래서 지진·침수·가스를 넣을 때 엔진을 고치지 않아도 된다.

**발화점 추첨** — 매번 다른 자리에 불이 나되, 시작 즉시 이길 수 없는 판은 내지 않는다.
후보마다 앞으로 몇 틱을 미리 돌려 목표까지 살아 갈 길이 남는지 보고 고른다.
`npm test` 가 시작 평면 전종 × seed 100 회로 이것을 확인한다.

**경로 판정** — 평면을 그래프로 바꾸고(방·개구부·출구), 통행 가능성 표에 따라 이어
목표 집합까지 닿는지 본다. 주 경로와 보조 경로는 서로 다른 `ScenarioKey` 로 각각 평가되므로,
현관이 막힌 상황을 가정한 보조 경로에는 다른 규칙이 걸린다.

## 접근성

포커스 표시 2px 아웃라인, `aria-pressed`/`aria-label` 부여, 색상 외 형태(아이콘·선 두께·점선)로도
상태를 구분한다. `npm run smoke` 가 편집·게임·리포트의 **모든 글자와 모든 단추를 전수로** 재어 확인한다.

| 항목 | 지키는 값 |
|---|---|
| 누르는 것의 최소 크기 | **48×48** (설계서 v1.1 §2.2 D6) — `--k-hit` 한 곳에서 정한다 |
| 본문 대비 | 4.5:1 (큰 글자 3:1) · 자동 검증 |
| 키보드만으로 | 된다 — Tab 으로 도면에 들어가 방향키로 칸을 옮기고 Enter 로 누른다 |
| 움직임 줄이기 | `prefers-reduced-motion` 존중 |
| 붉은 점멸 | 쓰지 않는다 |

도면을 다루는 데 마우스가 필요 없다. Tab 으로 도면에 초점을 주면 노란 칸이 나타나고,
방향키로 옮긴 뒤 Enter 를 누르면 그 자리를 누른 것과 같다. 방 놓기·문 놓기·내 방 고르기·
길 잇기·지우기가 모두 같은 길로 처리된다.

## 호환성

Chrome / Edge / Whale 최신 2개 버전.

| 화면 크기 | |
|---|---|
| PC (1024px 이상, 1280×800 이상 권장) | 된다 |
| 1024px 미만 화면 | 본 기능을 실행하지 않고 PC 이용 안내만 표시한다 |

`npm run smoke` 는 1024px 미만 화면에서 앱과 온보딩이 실행되지 않고 PC 안내만 나오는지 확인한다.
