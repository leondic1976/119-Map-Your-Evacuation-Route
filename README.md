# 우리집 대피지도

초등학생이 **우리 집을 블록으로 만들고**, 대피할 길을 그리고, **불이 난 집에서 직접 빠져나와 보는**
재난안전 학습 웹 앱이다. 끝나면 잘한 점과 고칠 점을 정리해 주고, 그때 그 장면을 **3D 로 다시 보여 주고**,
집에 붙일 **A4 대피지도 한 장**으로 뽑아 준다.

새 탭에서 처음 열면 행복한 어린이와 소방청 공식 캐릭터가 함께하는 소개 화면이 교육 목적을 알려 주고,
큰 「우리집 대피지도 그리기」 단추로 활동을 시작한다.

- 설치·회원가입·서버가 필요 없다. 브라우저만 있으면 된다.
- 그린 지도와 놀이 기록은 **서버로 전송되지 않는다.** 모든 연산과 저장은 이용자 기기 안에서만 이뤄진다.
- 인터넷이 없는 교실을 위해 **단일 HTML 배포본**을 제공한다. USB 로 옮겨 더블클릭하면 열린다.
- **점수·등급·순위를 매기지 않는다.** 시계는 줄어드는 제한이 아니라 늘어나는 시각이고,
  실패해도 잘한 점이 하나는 나온다.
- **PC 전용**이다. 너비 1024px 미만에서는 본 기능을 실행하지 않고 PC 이용 안내를 보여 준다.

> 이 앱의 확산 해석은 소방 교육자료에서 통용되는 눈높이 수치를 채택한 **교육용 근사 모델**이며,
> 성능위주설계(FDS 등) 해석을 대체하지 않는다. 또한 **법정 피난안내도를 대체하지 않는다.**

## 왜 만들었나

공동주택 화재 사망자의 다수가 연기·유독가스 흡입(77.9%)과 야간 인지 지연(19–07시 61.6%)에서 발생한다.
집집마다 평면과 피난시설이 제각각이라 "우리 집 기준"의 대피계획이 필요하지만, 아이가 직접
그려 보고 몸으로 익혀 볼 도구가 없었다.

## 하는 일

```
소개 ──▶ 그리기 ──▶ 대피경로 그리기 ──▶ 대피 게임 ──▶ 결과 리포트 ──┬──▶ 3D 로 다시 보기
           ▲              ▲                                       │
           │              └──────── [다시 해보기] ─────────────────┤
           └──────────────────────── [지도 고치기] ────────────────┘
```

| 축 | 하는 일 |
|---|---|
| 소개 | 행복한 어린이가 대피지도를 보는 배경과 소방청 공식 캐릭터 영이·일구·웅이를 보여 준다. 화재 때 신속하게 대피하는 방법을 미리 연습한다는 목적을 짧게 설명하고, 큰 시작 단추와 소방 심벌·부평소방서 표기로 활동의 출처와 다음 행동을 분명히 한다. 같은 탭에서는 한 번만 보인다. |
| 그리기 | 시작 평면 **8종**(방2·방3·방4·타워형·원룸·빌라·단독·복층)에서 출발해 방을 끌어 옮기고 크기를 바꾼다. 빈 도면에서 시작해도 된다. 팔레트 클릭 → 도면 클릭이면 표준 크기로 놓인다. 문이나 통과할 수 있는 발코니 창이 하나도 없는 방은 캐릭터가 이름을 말하고 문 도구와 방을 강조한다. 문을 골라 원하는 방 벽을 누르면 놓인다. 겹치는 배치는 시도부터 막는다. 기본 팔레트는 7종 + 더보기 = 8칸. 마우스가 없어도 Tab·방향키·Enter 로 다 된다. |
| 필수와 그 밖 | 현관문·방문·내 자리·소화기·감지기가 **필수**다. 팔레트에 채움 표시가 붙고 점검 막대에 `있어야 하는 것 3/5` 가 뜬다. 빠진 채로 시작하려 하면 한 번만 물어보고, 막지는 않는다. |
| 문·창 | 개구부마다 **평소 열림/닫힘**이 있다. 도면에 그대로 보이고 골라서 한 번 눌러 바꾼다. 방화문 닫힘이 방문 닫힘보다 잘 막고, 닫힌 창은 연기를 막고, 열린 창은 오히려 돕는다. |
| 나가는 곳 | 1층 밖·**옥상**·**지하** 세 갈래다. 평소 길은 아래로 나가고(RULE-F-08), 불이 나면 지하로 내려가지 않는다(RULE-F-09). |
| 경로 | **주 경로**(현관)와 **보조 경로**(현관으로 못 나갈 때) 두 줄. 규칙 엔진이 각각 다른 `ScenarioKey` 로 평가한다. |
| 게임 | 2D 위험장 엔진. 발화점은 매번 랜덤이되 **시작 즉시 이길 수 없는 판은 내지 않는다.** 연기가 불보다 빠르고, 닫힌 문이 확산을 늦추며, 낮은 자세가 노출을 줄인다. 불과 연기는 단계로 나눠 그려 번져 나가는 앞머리가 보인다. 연습 모드(시간 무제한)가 기본, 도전 모드에서 게이지로 시간을 보인다. 엔진(`core/hazard/field.ts`)에는 재난 이름이 없고 프리셋 JSON 으로 받는다. |
| 시계 | **늘어나는 시각**이다. 줄어드는 제한이 아니라 나가기까지 몇 초 걸렸는지를 보이고, 성공하면 자기 최고 기록과 나란히 뜬다. 등수는 없다. |
| 소리 | 시작 신호음·감지기 경보(실물 T-3 패턴)·발소리·문 여닫는 소리·자세 소리·성공 팡파르를 Web Audio 로 합성한다. 캐릭터의 말은 브라우저 음성합성이 읽는다. 상단바에서 끌 수 있고, **실패에는 아무 소리도 내지 않는다.** 음원 파일은 싣지 않는다. 읽히는 문장은 `VOICE-SCRIPT.md` 에 모아 두었다. |
| 3D 리플레이 | 리포트에서 「3D 로 다시 보기」를 누르면 같은 판을 3차원으로 재생한다. 기본은 **집 전체**를 비스듬히 내려다보는 인형집 구도다 — 벽을 허리께에서 잘라 안이 다 보인다. 바닥에는 **아이가 그린 길이 초록으로 빛나며 화살표가 흐르고**, 실제로 지나온 자취가 옅게 남아 둘을 견줄 수 있다. 나가는 곳에 표지가 서고, 불난 자리가 붉게 테두리 지고, 집 밖에는 잔디와 나무가 있다. 뒤에서·내 눈으로 시점도 있고, **끌어서 둘러보고 휠로 확대·축소**한다. 오른쪽 유리판에서 재생·빠르기·**겹 켜고 끄기**·화질을 다룬다. 무사히 나왔으면 마지막에 **가족이 반기는 장면**으로 넘어간다(성공했을 때만). 느린 기기에서는 후처리를 자동으로 끈다. WebGL 을 못 쓰면 2D 로 조용히 내려간다. |
| 리포트 | 규칙 엔진(정적)과 플레이 로그(동적)를 합쳐 **잘한 점 / 고칠 점**으로 정리한다. 실패해도 잘한 점이 하나는 있고, 고칠 점은 세 개까지만 보인다. `[왜?]` 를 누르면 학습 카드가 그 자리에서 펼쳐진다. 점수·등급·순위는 없다. |
| 캐릭터 | 영이·웅이(설명)와 일구(발견·격려)가 **트리거 기반**으로 먼저 말을 건다. 자유 입력·검색은 없다. "이제 뭘 해야 해?"는 어느 단계에서든 답한다. 말풍선은 도면 아래 **고정 높이 해설 칸**에만 나타나므로 지도를 가리지 않고 도면 크기도 바꾸지 않는다. 게임에서 내가 될 캐릭터는 **남학생 5명·여학생 5명** 열 명 중에 고른다. 얼굴 뼈대와 칠하는 방식은 같고 머리 모양·머리 색·피부 톤·옷 색·소품으로 갈린다. |
| 인쇄 | A4 세로 한 장 — 주·보조 경로, 못 나갈 때 미니맵, 우리 가족 약속, 손글씨 칸, 119, 가족과 함께 확인할 것. 흑백에서도 번호·선종류로 읽힌다. |

콘텐츠(학습 카드·캐릭터 대사·판정 문장·규칙 문장)는 `src/content/` 의 JSON 이다.
모든 문장에 출처 id 가 있고, 출처가 **1차 대조 전**이면 화면에 "검수 대기"로 표시된다.
`npm run validate` 는 구조 오류만 막고, `npm run validate:strict` 는 미검수 출처도 막는다
(소방청 원문 대조가 끝나면 배포 워크플로를 strict 로 바꾼다).

설계서는 `docs/DESIGN-v1.0.md` 와 변경 명세 `docs/DESIGN-v1.1-changes.md`,
`docs/DESIGN-v1.2-changes.md` 부터 `docs/DESIGN-v1.6-changes.md` 까지다. 어긋나면 뒤 문서가 이긴다.
받은 지시와 그 처리 상태는 `docs/REQUESTS.md` 에 모아 둔다.

### 명령

| 명령 | 내용 |
|---|---|
| `npm run dev` | 개발 서버 |
| `npm run build` | 정적 내보내기 → `out/` |
| `npm run typecheck` | TypeScript strict 타입 검사 |
| `npm test` | 연산 로직 · 배포 전 점검 54항목 (화면 없이 실행) |
| `npm run smoke` | Chromium 실조작 검증 33시나리오 (`npm run build` 후) |

| `npm run build:standalone` | 단일 HTML 배포본 → `dist/home-escape-map.html` |
| `npm run shots` | PC 화면 캡처 (`SHOT_VIEWPORT=1440x900`, 너비 1024px 이상) |
| `npm run voice` | `content/voice/*.mp3` 를 단일 HTML 안에 구워 넣는다 |
| `npm run verify` | 위 전부를 순서대로 (타입 검사 → 콘텐츠 → 로직 → 배포본 → 빌드 → 브라우저) |

smoke 를 처음 실행하기 전에 `npx playwright install chromium` 이 한 번 필요하다.
내려받기가 막힌 곳에서는 `SMOKE_CHROMIUM` 에 크로미움 실행 파일 경로를 준다.

## 배포

### 정적 웹

```bash
npm run build            # out/ 생성
```

`out/` 을 아무 정적 호스팅에나 올리면 된다. GitHub Pages 프로젝트 페이지처럼 하위 경로에
게시할 때는 기준 경로를 준다.

```bash
BASE_PATH=/저장소이름 npm run build
```

`main` 에 푸시하면 검증을 통과한 경우에만 GitHub Pages 로 배포하는 워크플로가
포함되어 있다(`.github/workflows/deploy.yml`). 저장소 설정에서
**Settings → Pages → Source: GitHub Actions** 를 한 번 지정하면 된다.

### 오프라인 배포본

```bash
npm run build:standalone
```

`dist/home-escape-map.html` 하나만 USB 로 옮기면, 인터넷이 없는 교실에서도
더블클릭으로 열린다. 외부 참조가 0건이 되도록 CSS·JS와 소개 화면 이미지를 전부 문서 안으로 넣고,
웹폰트는 시스템 글꼴로 대체한다.

HTML 에서 `<link>` 를 지우는 것만으로는 부족하다. Next.js 는 같은 참조를 스트리밍
페이로드에도 실어 보내고, 수화 과정에서 React 가 그것을 다시 넣기 때문이다. 그래서
빌드 자체를 오프라인 모드로 다시 돌려 웹폰트를 아예 렌더하지 않게 하고, 페이로드에 남은
스타일시트 경로는 내용이 담긴 data URL 로 바꾼다. `npm run smoke` 가 `file://` 에서
네트워크 요청 0건·오류 0건을 실제로 확인한다.

### 데스크톱 앱(Electron)으로 감쌀 때

바깥 세계에 닿는 코드를 `src/platform/` 한 곳에 모아 두었다. Electron 껍데기는
`Host` 를 구현해 `setHost()` 로 한 번 갈아 끼우기만 하면 되고, 나머지 코드는 손대지 않는다.

| 자리 | 웹 | 데스크톱에서 바꿀 것 |
|---|---|---|
| `platform/host.ts` | `localStorage` · `sessionStorage` · `<a download>` | 파일 시스템 · 저장 대화상자 |
| `platform/raster.ts` | 캔버스로 SVG→PNG | 그대로 쓴다 |

`npm test` 가 이 경계를 지킨다 — `platform/` 밖에서 브라우저 저장소나 파일 내려받기를
만지면 실패한다. 화면은 이미 `file://` 에서 네트워크 없이 도는 것이 검증돼 있으므로,
`out/` 이나 단일 HTML 을 그대로 실어 주면 된다.

## 구조

```
src/
  app/                 Next.js 진입점 — 화면은 하나뿐이다
  platform/            바깥 세계에 닿는 단 한 곳 (저장소 · 파일 · 래스터화)
  types/               평면 · 그래프 · 위험장 · 게임 · 리포트 · 저장 포맷
  content/             JSON 콘텐츠 — 블록 43종 · 시작 평면 8종 · 학습 카드 · 캐릭터 대사 · 규칙 문장
  core/                화면을 모르는 순수 계층 (react·zustand·window 를 부르지 않는다)
    grid               칸 점유 · 기하 · 방별 문 누락 검사
    graph              평면 → 그래프 · 통행 가능성 · 경로 탐색
    rules              검증 규칙 17개 (공통 8 + 화재 9) · 확장판 규칙은 따로
    hazard             위험장 엔진 (재난 이름을 모른다) · 발화점 추첨 · 확산 감쇠
    game               게임 진행 · 사람 상태 · 플레이 로그 · 리플레이 기록
    report             잘한 점 / 고칠 점 생성
    guide              캐릭터 대사 선택기 (트리거 기반)
    checklist          필수 물건 점검
  store/               zustand 상태 · 실행취소 · 자동저장 · 저장 스키마 이행
  ui/                  소개 화면과 학습 화면 — PlanSvg 하나를 에디터·게임·인쇄가 함께 쓴다
    replay3d/          3D 리플레이 — three · @react-three/fiber
      Scene            장면 전체 (집 · 길 · 표지 · 집 밖 · 불연기 · 카메라)
      RoutePath        바닥에 흐르는 빛나는 길
      Markers          나가는 곳 · 안전한 곳 · 불이 난 곳
      labels           3D 안의 한글 글자 (캔버스 텍스처 · 글꼴을 받아오지 않는다)
      quality          화질 두 단 · 느린 기기 자동 감지
    sound              감지기 소리 합성 · 음성 읽기
tools/
  test.ts              검증 틀 — 아래 둘을 부른다
  logic-tests.ts       연산 로직
  qa-tests.ts          배포 전 점검 (외부 호출 · 크기 · 이모지 · 층 경계 · 죽은 CSS)
  smoke.ts             Chromium 실조작
  standalone.ts        단일 HTML 빌더
  validate.ts          콘텐츠 게이트
  shots.ts             화면 캡처
```

3D 는 리플레이에만 있다 — 에디터·게임·인쇄는 전부 SVG 다.

의존 방향은 한 줄이다. `core` → 아무것도, `store` → `core`·`content`·`platform`,
`ui` → `store`·`core`·`content`·`platform`, `app` → `ui`. 거꾸로 가는 화살표는 없다.

### 핵심 알고리즘

**위험장** — 매 프레임 물리 연산 대신 칸마다 연료·감쇠를 두고 단계적으로 번지게 한다.
문·창이 열렸는지 닫혔는지, 방화문인지에 따라 감쇠가 달라지고, 연기가 불보다 빠르다.
엔진 자체는 재난 이름을 모르고 `content/hazards/*.json` 프리셋이 속도와 연료를 준다.
그래서 지진·침수·가스를 넣을 때 엔진을 고치지 않아도 된다.

**발화점 추첨** — 매번 다른 자리에 불이 나되, 시작 즉시 이길 수 없는 판은 내지 않는다.
후보마다 앞으로 몇 틱을 미리 돌려 목표까지 살아 갈 길이 남는지 보고 고른다.
`npm test` 가 시작 평면 전종 × seed 100 회로 이것을 확인한다.

**경로 판정** — 평면을 그래프로 바꾸고(방·개구부·출구), 통행 가능성 표에 따라 이어
목표 집합까지 닿는지 본다. 주 경로와 보조 경로는 서로 다른 `ScenarioKey` 로 각각 평가되므로,
현관이 막힌 상황을 가정한 보조 경로에는 다른 규칙이 걸린다.

## 접근성

포커스 표시 2px 아웃라인, `aria-pressed`/`aria-label` 부여, 색상 외 형태(아이콘·선 두께·점선)로도
상태를 구분한다. `npm run smoke` 가 편집·게임·리포트의 **모든 글자와 모든 단추를 전수로** 재어 확인한다.

| 항목 | 지키는 값 |
|---|---|
| 누르는 것의 최소 크기 | **48×48** (설계서 v1.1 §2.2 D6) — `--k-hit` 한 곳에서 정한다 |
| 본문 대비 | 4.5:1 (큰 글자 3:1) · 자동 검증 |
| 키보드만으로 | 된다 — Tab 으로 도면에 들어가 방향키로 칸을 옮기고 Enter 로 누른다 |
| 움직임 줄이기 | `prefers-reduced-motion` 존중 |
| 붉은 점멸 | 쓰지 않는다 |

도면을 다루는 데 마우스가 필요 없다. Tab 으로 도면에 초점을 주면 노란 칸이 나타나고,
방향키로 옮긴 뒤 Enter 를 누르면 그 자리를 누른 것과 같다. 방 놓기·문 놓기·내 방 고르기·
길 잇기·지우기가 모두 같은 길로 처리된다.

Chrome / Edge / Whale 최신 2개 버전.
