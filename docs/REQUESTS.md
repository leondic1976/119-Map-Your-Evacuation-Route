# 요청 관리대장

이용자가 말한 것을 하나도 흘리지 않기 위한 문서다. **새 지시를 받으면 먼저 여기에 적고**,
끝내면 상태를 고친다. 미이행이 남아 있으면 보고할 때 그 사실을 함께 말한다.

- **함** — 코드에 들어갔고 검증을 통과했다
- **하는 중** — 손대고 있다
- **막힘** — 이용자가 무언가를 해 주어야 진행된다
- **대기** — 아직 시작하지 않았다

설계서 반영이 필요한 것은 `docs/DESIGN-v1.x-changes.md` 에 먼저 적는다 (작업지침 §9).

### 20번 메모 — 3D 주인공을 게임 캐릭터처럼

지금 3D 의 사람은 `geometry.ts` 의 `buildPerson` 이 만드는 **색 입힌 상자 몇 개**다.
캐릭터를 고르면 옷 색만 바뀐다. 2D 의 `KidToken` 은 머리 모양 10종·머리 색·피부 톤·소품까지
갈리는데, 그것이 3D 로 넘어가지 않는다.

라이브러리 없이도 할 수 있는 길이 셋이다.

| 길 | 하는 일 | 드는 값 |
|---|---|---|
| A. 지금 몸에 얼굴을 붙인다 | `KidToken` 을 캔버스에 구워 텍스처로 만들어 머리 앞면에 붙인다. 몸은 지금 상자 그대로 | 작다. `labels.ts` 의 방식을 그대로 쓴다 |
| B. 부위별로 세운다 | `KidSpec`(머리 모양·색·피부·옷)을 읽어 머리·몸통·팔다리·머리카락·소품을 코드로 만든다. 걷는 시늉도 넣는다 | 중간. 캐릭터 10종이 다 달라 보인다 |
| C. 모델 파일을 들인다 | GLTF 로 만든 캐릭터를 넣는다 | **안 된다.** 자산을 파일로 두지 않는 규칙(FR-11.2)과 4MB 상한에 걸린다 |

**추천은 B 다.** A 는 옆에서 보면 얼굴이 납작해 보이고, 아이는 자기 캐릭터를 뒤에서 본다.
B 로 하면 머리 모양과 소품까지 3D 로 서고, 걸을 때 팔다리가 움직여 "게임 같다"는 느낌이 난다.

**이용자가 해 주실 일은 없다.** 캐릭터 정의(`KidSpec`)가 이미 있어서 제가 그대로 3D 로
옮기면 된다. 13·14번(게임다운 연출)과 함께 하는 것이 자연스럽다.
