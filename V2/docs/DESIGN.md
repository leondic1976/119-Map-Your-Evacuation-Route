# 우리집 대피지도 V2 설계서

대장 #109. 「지도 그리기가 어린이에게 너무 어렵다」는 의견을 받아 처음부터 다시 만든다.
지금 판(저장소 루트)은 참고만 하고 코드를 잇지 않는다. 이 문서가 V2 의 정본이고, 구현과 어긋나면 이 문서를 먼저 고친다.

## 1. 한 줄 요약

점과 점을 이어 집을 그리면 칸이 저절로 생긴다. 칸을 「방」과 「지나가는 곳」으로 나누고, 벽에 문을 달고,
칸을 차례로 눌러 나가는 길을 고른다. 그 길로 대피 연습을 하고 3D 로 다시 본다.

## 2. 이용자가 정한 것

| 항목 | 결정 |
|---|---|
| 범위 | 그리기 · 나가는 길 · 인쇄 · 대피 연습 · 3D 다시 보기 전부 |
| 공개 | 기본 주소를 열면 V2 로 간다(대장 #111). 앱은 `/V2/` 에 있다 |
| 벽 그리기 | 모눈 점 잇기. 둘러싸이면 칸이 저절로 색칠된다 |
| 나가는 길 | 칸을 차례로 누른다 |
| 학년 | 1~2 · 3~4 · 5~6 세 단계. 높을수록 지도가 더 자세해진다 |
| 낱말 | 쉬운 말만 쓴다. 「구획실」「통로」는 화면과 음성에 쓰지 않는다 |
| 기기 | PC 와 태블릿. 마우스와 손가락이 같은 조작이다 |
| 캐릭터·음성 | 일구·영이·웅이와 Juwonmom 목소리를 유지하고 대사를 새로 녹음한다 |
| 화면 느낌 | 모눈 스케치북 — 모눈 종이, 연필 선, 크레용 색칠 |

## 3. 낱말

| 설계 용어 | 화면 말 | 아이에게 하는 설명 |
|---|---|---|
| 구획실 | 방 | 문을 닫으면 불과 연기를 막아 주는 칸 |
| 통로 | 지나가는 곳 | 밖으로 나갈 때 걸어가는 칸 |
| 격자점 | 점 | |
| 경로 | 나가는 길 | |
| 집결지 | 만나는 곳 | |

## 4. 학년 단계

기능을 숨기기만 하는 것이 아니라 **지도에 담기는 정보**가 단계마다 늘어난다.

| | 1~2학년 | 3~4학년 | 5~6학년 |
|---|---|---|---|
| 모눈 | 8×6 | 10×7 | 12×8 |
| 시작 | 집 본 3종을 골라 연한 선을 따라 그린다 | 겉모양 본을 고르고, 벽은 직접 나눈다 | 빈 모눈에서 직접 그린다(본도 고를 수 있다) |
| 칸 이름 | 방 · 지나가는 곳 | + 내 방 · 부엌 · 화장실 · 거실 · 현관 등 | 같음 + 복도 · 베란다 |
| 문과 창 | 문 | 문 · 창문 | 문 · 창문 |
| 놓는 것 | 내 자리 · 만나는 곳 | + 불 조심(가스레인지) · 소화기 | + 화재 감지기 |
| 나가는 길 | 한 길 | 한 길 | 두 길(둘째 길은 권유하고 막지 않는다) |
| 대피 연습 | 몸 낮추기 | + 뜨거운 문 확인 | + 지나온 문 닫기 |

어느 단계든 「도와줘」를 누르면 무난한 기본값이 채워져 막다른 길로 가지 않는다.

## 5. 흐름

첫 화면 → 이름표(이름 · 학년 · 내 모습) → 아래 일곱 단계. 단계 띠로 앞 단계에 언제든 돌아갈 수 있다.

첫 화면의 캐릭터는 표지 그림 아래에 나란히 선다. 폴짝 뛰어도 서로와 표지, 글, 단추, 아래 문구에 겹치지 않고, 시나리오가 네 가지 화면 크기에서 잰다(대장 #128 · #129). 일구 그림은 옆 캐릭터 조각을 지운 파일을 쓴다. 캐릭터 출처는 설정과 인쇄물에 적는다.

첫 화면은 살아 움직인다(대장 #119, `ui/WelcomeScene.tsx`). 구름·해·새·나무·창문·소방차·걸어가는 가족·깃발이 CSS 로 움직이고, 표지 그림은 집을 그리고 길을 따라 나가는 모습을 14 초마다 되풀이하며, 캐릭터가 폴짝 뛰고, 손을 따라 배경이 조금 움직인다. 바깥 자산은 없다. 빛을 깜박이지 않고 시작 단추의 자리는 움직이지 않는다. 움직임 줄이기를 켠 기기에서는 다 그려진 그림으로 멈춘다.

1. **집 그리기** — 점을 잇는다. 끌면 점을 따라 선이 생기고, 점을 차례로 눌러도 된다.
2. **칸 나누기** — 칸을 눌러 방 또는 지나가는 곳으로 정한다.
3. **문 달기** — 벽 선을 누르면 문, 바깥 벽의 문은 밖으로 나가는 문이다.
4. **표시하기** — 내 자리와 만나는 곳 등을 놓는다.
5. **나가는 길** — 내 자리 칸에서 시작해 갈 수 있는 칸을 차례로 누른다. 갈 수 있는 칸은 늘 빛난다.
6. **대피 연습** — 칸을 눌러 움직이는 차례 진행. 시간제한이 없다.
7. **돌아보기** — 잘한 점 · 고칠 점(세 개까지) · 3D 다시 보기 · 인쇄.

첫 화면에 지도가 있으면 「이어서 그리기」 옆에 「처음부터 다시 하기」가 있다(대장 #120). 한 번 묻고 이름표는 남긴 채 종이만 새로 깐다.

할 일을 다 하면 다음에 무엇을 할지 말해 주고 「다음」 둘레에 물결이 퍼진다(대장 #121). 집 테두리를 처음 닫으면 안에 선을 그어 방을 만들자고 하고, 칸이 둘 이상이면 다음으로 가자고 한다. 칸 나누기·문 달기·표시하기·나가는 길도 끝낼 때 한 번씩 알려 준다. 끝난 단계에 다시 들어왔을 때는 말하지 않는다.

## 5.1 사용법 (대장 #113)

「눌러야 하는지 방향키인지 처음에 모른다」는 이용자 의견으로 더했다.

- 단계에 처음 들어가면 **사용법 카드**가 한 번 뜬다. 손가락이 직접 눌러 보이는 움직이는 그림 · 짧은 글 두세 줄 · 음성이다.
  「알겠어」 한 번으로 닫히고, 닫기와 `Esc` 도 된다. 본 단계는 이 기기에 기억해 다시 뜨지 않는다.
- 아래 줄의 **「어떻게 해?」** 로 어느 단계에서든 다시 본다. 돌아보기에는 조작이 없어 없다.
- 나가는 길과 대피 연습에서는 갈 수 있는 칸마다 **손가락과 「여기를 눌러」** 를 띄운다.
- 나가는 길과 대피 연습은 **키보드 화살표**로도 움직인다. 지금 자리에서 그 방향에 있는 문으로 간다. 그쪽에 문이 없으면 말로 알려 준다.
- 대피 연습은 경보 안내가 끝나면 움직이는 법을 이어서 말한다.
- 위 띠 왼쪽의 **집 모양 단추**와 설정의 「처음 화면으로」로 언제든 첫 화면에 돌아간다. 지도와 이름표는 남고, 첫 화면에서 이어서 그린다.

## 6. 데이터

점수 없음. 저장은 이 기기 안(`localStorage`)에만 한다. 서버로 아무것도 보내지 않는다.

- 벽 조각: 이웃한 두 점 사이 한 칸 길이. 벽은 조각의 집합이다.
- 칸: 벽으로 막혀 바깥과 이어지지 않는 네모들의 묶음. 벽에서 매번 계산하고 저장하지 않는다.
- 칸 표지: 네모 하나에 붙는 종류와 이름. 칸이 갈라지면 표지가 있는 쪽만 이름을 유지한다.
- 문·창: 벽 조각 위에 놓인다. 벽이 지워지면 함께 지워진다.
- 나가는 길: 칸 표지가 아닌 대표 네모의 나열이며, 벽이 바뀌면 다시 검사해 끊긴 뒤쪽을 버린다.

## 7. 대피 연습 규칙

- 한 번 움직일 때 위험도 한 번 퍼진다. 시계로 줄어드는 시간이 없다.
- 위험은 연기 → 불 순서로 문을 따라 번지고, 닫힌 문은 늦춘다.
- 발화 칸은 시드로 고르되, 가장 짧은 길로 나갈 수 있는 칸만 고른다. 내 자리 칸에서는 시작하지 않는다.
- 불이 막아 갈 곳이 없으면 실패가 아니라 「문을 닫고 창가에서 119에 구조 요청」으로 끝난다.
- 점수·등급·순위 없음. 잘한 점은 하나 이상, 고칠 점은 세 개까지. 붉은 점멸 없음. 실패음 없음.
- 위험장 엔진(`core/hazard.ts`)에는 재난 이름을 넣지 않는다. 화재 수치는 `content/fire.ts` 에서 넣는다.

## 8. 화면 원칙

- 누르는 크기 48×48 이상, 점의 누르는 범위도 48 이상. 모눈 간격이 48 아래로 내려가면 태블릿 안내를 낸다.
- 한 화면에 큰 단추 하나가 주인공이다. 상단에 단추를 늘어놓지 않는다.
- 한글은 `word-break: keep-all`. 이모지 금지, 그림은 전부 벡터.
- 덮개에는 닫기와 `Esc` 를 둔다.
- 움직임 줄이기 설정을 존중한다.
- 폭 720px 미만은 태블릿이나 컴퓨터에서 열라는 안내만 보인다.

## 9. 음성

캐릭터가 소리 내어 말하는 문장은 `src/content/lines.ts` 한 곳이 정본이다. 각 문장은 `public/voice/<id>.mp3` 로
재생하고, 없거나 실패하면 글만 남기고 조용히 멈춘다. 브라우저 음성합성은 쓰지 않는다.
`npm test` 가 정본과 `public/voice/manifest.json` · MP3 파일 대조를 맡고, `npm run smoke` 가 전 파일을 해독해 말 길이를 잰다.

제작 설정은 지금 판과 같다: `Juwonmom` · Eleven Multilingual v2 · Speed 1.0 · Stability 50 · Similarity 75 · Style 0 · Speaker Boost 켬.
서 있는 자세의 그림만 쓴다(공식 그림의 보통 자세는 침대에 누운 모습이고 생각 자세는 책상 앞이다).

## 10. 안전 문장 출처

모든 안전 문장은 `sourceIds` 를 갖고 `content/sources.ts` 에서 찾는다. `verified: false` 인 출처의 문장은
돌아보기와 인쇄물에 「검수 대기」를 함께 보인다.

## 11. 층

```
core  → 아무것도 부르지 않는다 (순수 계산)
store → core · content · platform
ui    → store · core · content · platform
```

`localStorage`·인쇄·오디오처럼 바깥에 닿는 일은 `platform/` 에서만 한다. `three` 는 `ui/replay3d/` 에서만 부른다.
`tools/qa-tests.ts` 가 이 경계를 검사한다.

## 11.1 비스듬한 벽 (대장 #115 · #116)

- 벽의 두 끝은 언제나 점이고 어떤 두 점이든 곧게 잇는다. 각도가 정해져 있지 않다. 벽 조각은 가로(`h`)·세로(`v`)·45도(`d` · `u`)·그 밖의 각도(`s:x1:y1:x2:y2`)이고, 줄 위의 점마다 나뉜다.
- 비스듬한 벽이 지나는 네모는 볼록한 조각들로 나뉜다. 끝이 점이라 벽은 네모를 언제나 끝까지 가로지르므로 네모마다 줄로 자르면 된다. 칸·표지·표시·길은 조각을 단위로 쓴다(`x,y` · `x,y:ne` · `x,y:c3333_6667`). 벽을 지우면 다시 네모 하나가 된다.
- 조각은 볼록하므로 길은 조각 가운데와 맞닿은 변의 가운데를 번갈아 지나 벽을 뚫지 않는다.
- 벽끼리 엇갈려도 된다. 엇갈린 벽은 토막으로 나뉘고(`벽#0.5-1`) 문과 창은 토막에 달린다. 벽이 나중에 엇갈려도 문은 있던 자리의 토막으로 옮겨 간다. 지우개는 벽 하나를 통째로 지운다.
- 점이 비스듬한 벽 위에 없어 안쪽 벽을 넘겨 그을 수밖에 없을 때가 있다. 칸에 붙은 벽을 넘어 집 밖으로 삐져나온 꼬리는 그리지 않고 문도 달리지 않는다.
- 끌어서 그릴 때 손이 줄에서 벗어나면(0.24 ~ 0.4 칸, 긴 줄일수록 너그럽다) 곧은 줄이 아니다. 곧지 않게 온 점은 0.25 칸 안까지 와야 꺾은 것으로 본다. 그래서 스쳐 지나는 점에 꺾이지 않으면서 네모 집의 모서리가 깎이지 않는다. 점을 차례로 누르면 곧게 잇는다. 예전에는 멀리 떨어진 점을 누르면 ㄱ자로 꺾였다.
- 「아파트 모양」 레이어의 「다른 모양」에 「비스듬한 집」(45도)과 「뾰족한 집」(다른 각도)이 있다.
- 3D 의 가구는 칸 이름에 맞춰 저절로 놓는다(`core/furnish.ts`). 벽에 등을 대고 비스듬한 벽에는 비스듬히 붙으며, 들어가지 않으면 눕혀 보고 줄이고 작은 한 벌로 바꾼다. 세모뿐인 칸에도 들어간다. 벽·지나는 길·문 앞에 닿지 않으며, 자리가 없으면 놓지 않는다. 아이가 고르는 조작은 늘리지 않았다.

## 11.2 지도 크게 보기 (대장 #117)

- 같은 학년이라도 손 솜씨가 다르다. 크게 보면 점 사이가 넓어져 같은 손 떨림이 줄어드는 셈이다. 전체를 보며 그리는 아이는 그대로 쓰면 된다.
- 그리기·칸 나누기·문 달기·표시하기·나가는 길·대피 연습에서 쓴다. 1배(전체 보기)에서 4배까지이고 전체보다 작아지거나 지도 밖으로 밀리지 않는다(`core/zoom.ts`).
- 기준 점 — 단추는 잡아 둔 점이 있으면 그 점, 없으면 지금 보는 곳의 가운데다. 휠은 손 아래 점, 손가락 둘은 손가락 사이다. 기준 점은 화면에서 제자리에 있다.
- 옮기기 — 단추(끌면 종이가 움직인다) · 손가락 둘 · 마우스 가운데 단추. 그리는 중에 손이 가장자리에 닿으면 종이가 따라온다.
- 크기는 단계를 넘어도 유지하고 저장하지 않는다. 인쇄와 돌아보기는 언제나 전체를 보인다.

## 11.3 점 개수 (대장 #122 · #125)

- 집 그리기 왼쪽의 빼기·더하기 단추로 점 개수를 하나씩 바꾼다. 학년 단계마다 기본 개수에서 50% 안팎으로 줄고 늘어나고(`BANDS[].grids`, 1~2학년 35~88개 · 3~4학년 48~130개 · 5~6학년 63~176개), 더 세밀히 그리고 싶을 때 쓰는 배수(×2 · ×4)가 그 뒤에 있다.
- 지도의 좌표는 언제나 지금 점 단위다(`plan.density`, `core/density.ts`). 그림은 같은 너비로 그리므로 칸·문·길 계산은 이 값을 모른다.
- 바꿀 때 벽 끝은 가장 가까운 점으로 옮겨 간다. 배로 늘리면 그대로 남고, 그 밖의 개수는 벽이 조금 움직일 수 있으며 점이 적으면 작은 칸이 사라질 수 있다. 막지 않고 되돌리기로 돌아가게 한다.
- 배로 늘렸을 때는 처음 점을 크게 그려 자리를 잡기 쉽게 한다.
- 손은 점이 촘촘해진다고 덜 떨리지 않는다. 곧은 줄 판정, 꺾임 판정, 벽 누르기 거리를 손 떨림 단위(`간격 ÷ 확대 배율`, 1 이상)로 맞춘다. 전체 보기에서 촘촘한 점에 그리면 가로세로 벽이 비스듬해지지 않게 잡아 주고, 크게 보면 한 칸짜리 턱까지 정확히 그린다.
- 문과 창은 벽 조각이 짧아도 제 크기로 낸다. 그림은 곧게 이어진 벽 위에 얹고, 3D 는 곧게 이어진 벽을 한 줄로 지어 구멍을 뚫는다. 표시 사이는 처음 네모 한 칸쯤 띄운다. 3D 와 가구, 불꽃은 처음 네모 단위로 그대로다.

## 11.4 아파트 모양과 가구 (대장 #123 · #126)

- 지도에 깔리던 연한 점선과 왼쪽의 「집 모양 본」을 없앴다. 왼쪽 패널 폭은 110px 이다. 빈 종이에서 시작하고 「도와줘」는 그대로 기본 집을 채운다.
- 「아파트 모양」과 「가구」는 패널의 단추로 여는 레이어다. 고르지 않아도 지도를 끝까지 만든다.
- 아파트 모양은 우리나라의 흔한 평면을 쉬운 말로 옮겼다. 방 2개(작은 집), 방 3개(전용 59㎡ 안팎 · 3베이 · 화장실 2), 방 3개 넓게(84㎡ 안팎 · 4베이), 방 4개(큰 집), 꺾인 집(타워형 · 창이 두 쪽), 긴 집(앞뒤로 창). 모두 거실·주방·화장실·현관·베란다가 있고 대부분 다용도실이 있다. 면적과 방 수의 대응은 공식 규격이 아니라 분양 보도에서 흔한 구성이다.
- 글자로 그린 12×8 평면을 점 개수에 맞춰 짓는다(`content/homes.ts`). 점이 기본보다 적으면 기본 개수까지 늘려 작은 칸이 사라지지 않게 한다.
- 베란다 크레용은 전 학년에 있고 다용도실은 3학년부터 있다. 베란다로는 나가는 문을 달지 않고, 현관이 있으면 현관으로 나간다. 현관과 집 안 사이의 문은 지도에 「중문」으로 적는다.
- 가구는 15가지를 방·거실·주방·화장실·베란다와 현관으로 묶었다(`content/items.ts`). 고른 뒤 지도를 누르면 칸 안에 놓이고 가장 가까운 벽을 저절로 등진다. 돌리는 조작은 만들지 않았다. 집 그리기와 표시하기에서 놓고 치운다.
- 놓은 가구는 지도·인쇄·3D 에 나오며 대피 길을 막지는 않는다. 아무것도 놓지 않은 칸은 3D 에서 칸 이름에 맞는 가구로 저절로 채운다(`core/furnish.ts`).

## 11.6 돌아보기와 3D (대장 #127)

- 연습 전 돌아보기는 다 됐다는 말과 「대피 연습 하러 가기」를 오른쪽 칸 가운데에 모은다.

## 12. 배포

- `V2/` 는 독립 프로젝트(Vite · React · TypeScript)다. 자체 `package.json` 을 갖는다.
- 빌드는 상대 경로라 어느 하위 경로에 올려도 돈다. `deploy.yml` 이 `V2/dist` 를 Pages 의 `V2/` 에 함께 싣는다.
- 저장은 도면뿐이다(대장 #132). 기기에 오래 남는 것은 `localStorage` 의 도면 하나이고, 이름표·소리·단계·사용법을 본 기록은 탭이나 창을 닫으면 사라진다. 다시 열면 도면의 칸 수로 학년 단계를 알아내 이어서 그린다. 이름과 내 모습은 다시 고른다.
- 웹 판은 화면을 저장해 두지 않아 인터넷이 있어야 열린다. 인터넷 없이 쓰려면 윈도우 프로그램이나 오프라인 꾸러미를 받는다. `V2/sw.js` 와 `root-sw.js` 는 이전 판 워커를 넘겨받아 옛 저장본을 지우고 스스로 물러나는 워커이고, 화면도 열 때 남은 워커와 저장본을 지운다. 지울 때는 이 사이트의 것(`hem` 으로 시작하는 저장본, 사이트 아래 워커)만 지운다. 브라우저의 보통 HTTP 캐시는 GitHub Pages 가 정하는 10분 동안 남을 수 있다.
- 윈도우 프로그램은 켤 때와 여섯 시간마다 `download/latest.json` 을 읽어 새 판이면 묻지 않고 받아 sha256 을 맞춰 둔다. 그리는 도중에 꺼지지 않도록 창을 닫을 때 조용히 설치하고 다음에 켜면 새 판이다. 무설치판은 창이 닫힌 뒤 실행 파일을 새것으로 바꾼다. 받은 파일이 다르면 설치하지 않는다(대장 #131). 2.7.0 까지의 프로그램은 묻는 방식이라 그 판들은 한 번은 눌러서 설치해야 이후부터 저절로 된다.
- 판 기록은 안내 페이지와 `download/releases.json` 에 있다(대장 #130). 판마다 바뀐 것과 날짜를 보이고, 지금 판과 바로 앞 두 판의 설치판을 받는다. 출처는 `CHANGELOG.md` 와 Release `desktop` 이다.
- `deploy.yml` 이 `root-redirect.html` 을 사이트 첫 페이지(`index.html`)로 싣는다. 기본 주소를 열면 `/V2/` 로 간다.
- `/download/` 와 `latest.json` 은 그대로 둔다. 이미 깔린 설치판이 새 판 확인에 쓴다.
- 오프라인 판은 `npm run build:offline` 으로 `offline/` 에 만든다. file:// 에서 받을 수 없는 스크립트·스타일·글꼴을 HTML 한 장에 넣고(4MB 이내), 그림과 음성은 옆 폴더에 둔다.
- 루트의 `tools/standalone.ts` 가 이 폴더를 `dist/` 로 옮겨 꾸러미 ZIP 을 만들고, 윈도우 설치 파일이 같은 `dist/` 를 싣는다(대장 #110).
- 이전 판의 지도는 그리는 방식이 달라 V2 로 옮기지 않는다. 저장 키가 달라 이전 자료를 지우지도 않는다. V2 에는 파일로 저장·불러오기가 없고 인쇄만 있다.
